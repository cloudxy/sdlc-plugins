# 复刻与模块实现的方法增量（2026-11-14）

来源是一次已完成的软件维护切片及用户要求的复盘迁移，已去项目内容、账号、配置和媒体字节。原始证据保存在来源工作区，摘要指纹见 [origin-evidence.json](origin-evidence.json)；技术验证不作为专业效果或全站复刻批准。

## 观察到的失败与修正

| 观察 | 处理与退出证据 | 方法落点 |
|---|---|---|
| 有目录/URL仍被当成资源交付，脚本内嵌封面使用占位图 | 保存236原文件，索引/页面本地读取；114视频完整解码、122图解码、236 HEAD及114首尾Range通过；安装包核索引和维护入口 | compete的资源范围；impl-evidence的来源/字节/消费者分层 |
| 所有者、创建者、参与关系和浏览范围混在一起 | 按已接受归属规则划分互斥集合，列表与分页/数量一致；用户目录中隐藏不需要的身份字段 | architecture边界推导；design-contract信息架构 |
| 内外容器留白叠加、卡片提示和操作区易冲突 | 局部调整后看实际桌面布局；未验窄屏继续标未知 | design-contract局部复用与真实视口 |
| 同一工作树并行提交使候选HEAD/版本变化，运行接口仍暴露旧参数 | 核文件归属和候选版本，实际接口形状/非法参数及业务读回验证；旧加载机理没有充分根因证据 | deliver运行身份与就绪顺序 |
| 校验器把截帧图片ETag等同内容MD5，误报113图损坏 | 保留原检查输出，确认表示语义后重核受影响图片；未改写原始媒体来迎合错误判定 | impl-evidence校验语义；coverage-matrix检查器与产品缺陷区分 |
| 探针错误地预期400，实际契约422；旧服务退出未完就发批量检查 | 修正判定依据；按新实例单项就绪后再做批量读取，连接错误不当成资源坏 | coverage-matrix契约/实际结果；deliver停止/就绪/批量顺序 |
| 开发与发布的定向测试耗时差异明显 | 留范围与耗时，最后门禁确实通过；没有足够证据定位性能根因，不删必要测试或绕门禁 | deliver按影响检查与异常诊断 |

## 角色与方法连接

| 对应角色 | 既有Skill | 增强范围 |
|---|---|---|
| competitor | compete | 已选复刻目标的范围、资源与跨入口证据 |
| designer | design-contract | 集合语义、精简卡片、辅助标签和容器复用 |
| architect | architecture | 归属/创建/授权/浏览分开，覆盖互斥与生命周期 |
| frontend / backend | impl-evidence | 本地原文件、固定引用、真实消费者、读取及安装路径 |
| qa | coverage-matrix | 详情/预览/复制/下载/手势一致性与校验器反例 |
| sre | deliver | 候选版本、并行工作树、服务就绪与实际功能探测 |

身份、权限和写入范围继续由原注册表决定，角色产物不手改；方法从已有primary skill及其条件参考加载。不增加必经阶段、额外审批、固定模型/调用配额或所有产品必须本地化的全局规则。
