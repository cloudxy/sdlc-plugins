## 唯一分类规则与结果

先取当前调用者真实授权集合 `A(m)`；分类不能授予权限。对其内每条记录按稳定归属事实判定：

1. `owner_kind=team` → 团队。直接成员、邀请路径、创建者不改变此类。
2. `owner_kind=personal` 且 `owner_actor=m` → 个人。
3. `owner_kind=personal` 且 `owner_actor!=m` → 参与，前提仍是有访问授权。

创建是历史行为，归属是当前事实，授权决定可见，分类只是读投影。`owner_active=false` 不等于无主、无权限或不应显示。未知创建者不能从编辑者/角色/上下文猜出。

| 记录 | 分类／可见性 | 判定依据 | 卡片权限状态 |
|---|---|---|---|
| p1 | 个人 | personal，归 m；someone 创建不影响 | 未给出只读/编辑权限，不推断可写 |
| p2 | 团队 | team-a 的团队记录；m 创建、direct_member=true 都不改变归属 | 未给出只读/编辑权限，不推断可写 |
| p3 | 参与 | 他人个人归属，authorized=true；注销不删除历史归属 | 明确保留“只读”标签；不展示归属人/创建者 |
| p4 | 不可见，不计入三类 | authorized=false，即使 m 创建也不越权出现 | 不渲染该记录及其计数信息 |

给定样例的互斥分区为：个人 `{p1}`，参与 `{p3}`，团队 `{p2}`；并集 `{p1,p2,p3}` 等于全部已授权记录，两两交集为空。三类计数均 1，总可访问计数 3。这里只对给定记录作确定分类，不声称真实数据库已经满足。

全部可访问记录必须有合法且保留的归属事实。若后续存在其他 owner_kind、空 owner_actor 或不可解释归属，不可擅自塞进“参与”或新增第四类。由业务/数据 owner 修复或明确既有规则覆盖方式；分类总量检查应显式暴露异常，不能前端静默漏行并宣称全覆盖。本例无该歧义，不必等待新批准。

## 列表、计数、分页与生命周期

- 既有权威授权逻辑先过滤；同一归属分类投影供列表、计数、筛选选项和分页使用，不在各端点复制规则，也不从浏览的“当前空间”推断归属。
- 顺序：授权 → 适用搜索/筛选 → 分类条件 → 稳定排序（沿既有排序并以稳定唯一键消除并列歧义）→ 总量/分页。计数与列表使用相同用户、条件和可见快照；不得只在当前页前端删行。三类 tab 数量约定为“同样非分类筛选条件下各分区的总量”，而非本页长度。
- page/page_size、默认与上限、offset/cursor 沿既有分页契约；输入未提供，不能自创替换。若既有接口不提供 total，不能伪造 total；应复用其计数入口或将缺口交接口 owner。游标/缓存键绑定调用者、分类、筛选、排序与适用数据版本，变更分类/筛选重置页/游标，过期响应不得覆盖新筛选。
- 授权失效要同时影响列表、计数和详情。归属转移后从旧类移入新类，不重复；保留 created_by 历史未知值和历史归属记录，注销保留既有身份引用规则。谁转移、注销后授权如何演变沿业务既有权威，本轮不改。
- 同时请求的列表和计数若跨数据版本，应按既有一致性约定返回版本/重试，不能承诺未验证的事务隔离。权限加载中显示加载态，读取失败显示错误，不等同于空列表。

## 紧凑卡片增量

| 字段 | 本轮处置 | 展示契约 |
|---|---|---|
| cover | 保留 | 沿已批准尺寸与容器；无封面时显示“暂无封面”，不挤压操作区 |
| title | 保留 | 主识别信息；长标题按既有截断/换行规则，仍能取得完整标题 |
| date | 保留 | 沿既有日期含义和格式，不猜创建时间或修改时间 |
| type | 保留 | 沿既有类型命名，不扩业务枚举 |
| owner_name | 隐藏 | 同时移除正文、tooltip、title、aria-label/description 中的归属人姓名 |
| created_by | 隐藏 | 同时移除可见与辅助技术文字；不因未知值补造人物 |
| role | 不再作为关系信息堆在卡片 | 必要权限效果保留为只读状态“只读”；其余动作可用性由真实授权决定，不由分类/creator 推断 |

“只读”用文本而非仅颜色表达；p3 可浏览，写操作不可用，旁注“此记录只读”。卡片/打开按钮的可访问名称可用“打开〈标题〉”，不含归属人或创建者；只读说明通过现有状态语义关联。这里的“隐藏”是展示要求，并非修改审计事实或数据库；不自行删除已有接口字段、改 schema 或承诺网络响应中不含姓名。

样式消费现有深色容器、spacing/type/radius/focus/breakpoint tokens，不新增数值。保持键盘焦点、已批准触摸目标和操作顺序。需要检查外层与内层留白、最小宽度、长标题、无封面、窄屏、可访问树和 tooltip；本轮无运行界面，未观察任何断点、对比度或屏幕阅读器，不能标记设计验收通过。
