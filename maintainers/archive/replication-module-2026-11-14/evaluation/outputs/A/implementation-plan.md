## 契约与三个身份

固定引用原样保留：`demo-1@1`、来源 `https://cdn.example.test/demo.mp4`、契约摘要 `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`。不重写历史 URL、摘要、版本或请求快照。提供的字符串只是合成夹具；它们计算所得摘要不能替换此固定摘要，也不能证明原视频完整。

| 层次 | 本次事实及动作 | 责任与消费者 |
|---|---|---|
| 业务引用 | `demo-1@1` 为稳定查找键；原引用只读 | 契约所有者维护；UI 只消费 |
| 原视频字节 | `video.bin` 保存合成的 `original video bytes`；记录实际 SHA-256、长度、声明类型，状态 synthetic | 获授权资源导入者；不冒充有效 MP4 |
| 派生封面字节 | `cover.bin` 保存合成的 `derived snapshot bytes`，单列身份 `demo-1@1/cover`、转换参数 `snapshot_at_0` 和来源关系 | 导入者维护，grid 消费；不与源视频共用摘要 |
| 方法封面 | 已提供 inline data URI，可离线提取为独立合成字节；WebP 解码未验证 | 后续导入者；不能因有 data URI 声称资源可展示 |
| 实际消费者 | grid→本地封面；dialog、download→本地视频；原先三个远程 URL 都需迁移 | UI owner 实施；真实集成由 slice_integrator 留证 |

两份响应同为 `eeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee` 的 ETag，语义未给出，按不透明缓存标识保存。它既不证明文件相同，也不能当 MD5 进行完整性判定。合成验证保留这种错误验证器的失败反例，然后用对应夹具的已知 SHA-256 检查当前字节。原业务固定摘要与合成视频摘要不符，仍明确列为“真实来源完整性未验证”，不把修复验证器等同于源视频通过。

## 最小实施顺序

1. 以既有媒体根目录为边界，补资源身份到本地对象映射；不在业务历史记录中替换 URL。清单区分资源记录数、唯一文件数与转换关系。本输入只有一段视频、一份封面、一份内嵌方法封面；不能外推整库覆盖。
2. 显式导入负责读取来源，先写临时对象、核当前表示的长度/摘要和实际解码，再发布映射。失败保留既有好文件。资源读取入口只接受稳定 ID/版本和既有授权，禁止任意 URL 代取、路径逃逸或自动联网恢复。
3. UI 同批替换 grid、dialog、download 的实际请求；清查详情、预览、CSS、poster、内联图与错误回调。缺失/损坏显示“本地资源不可用”，提供已授权的显式恢复入口。不能暗中回退 CDN。来源追溯字段可继续保留原 URL。
4. 真实视频接口按既有框架核 GET/HEAD、Content-Type/长度、Range（首尾分段与越界）、条件请求和权限。检查安装后路径、媒体目录备份与映射索引，不能只验证开发目录。
5. 用真实媒体、真实后端及批准的最终原型，在 grid→dialog→download 走查；浏览器网络记录证明消费本地字节，分别核下载摘要与实际播放/拖动。打开同状态截图对照原型，保留空/加载/错误/边界/权限/离线证据。没有这些证据不关闭 UI 集成。

本轮不新增 schema、tokens 或 API 规范，不替其他角色做业务选择。真实原型版本、组件 ID、flows、edge-states、后端接口及 tracking 未随输入提供；不会伪造。它们是生产实施前补齐的输入，并不阻止本轮已授权的方案和合成校验。

## 复现与验证范围

`verify.py` 只使用 Python 标准库，写入本目录下 `fixtures/` 与 JSON 结果；不启动服务、不联网、不触碰生产源文件。它检验错误 ETag 校验器、对应字节摘要、三处消费者静态配置、固定引用不变、路径逃逸、缺失/损坏拒绝及内嵌资源提取。它不运行浏览器、服务器或媒体解码器。

执行记录及逐检查结果见 `commands.json`、`legacy-etag-result.json`、`verification-result.json`。其中负例退出 1 是实际被检测出的错误验证方式，不是忽略的失败。修正逻辑通过仅证明本合成夹具的检查策略可工作。
