| 原项目经验 | 可复用方法 | 限制与本轮位置 |

| 点击账本、日志容量门禁 | 在预算或容量边界前让出任务；关键计量失败停止依赖操作；补传/清理仍可运行 | collect、schema；普通诊断可降级，阈值和恢复条件由实际访问约定/负载决定 |
| 已知边界与证据 | 用既有风险/ADR 表记录影响、负责人及复审条件；区分模拟、临时真库与生产交付 | architecture、两份新参考；不增加固定编号、额外流程或自动闸门 |

## 未采纳的推论

- “最终值日志换原子性”：实现会依次 DEL、RPUSH、HSET 等；本进程锁不能阻止其他进程或不遵循恢复协议的读取者。
- “所有采集失败统一零重试/次日恢复”：页面业务操作、资源探测与幂等的提交恢复有不同条件。
- “所有来源完整才发布”“计量失败整个集群停”：发布范围与影响范围必须来自业务契约和实际共享依赖。
- 拟人化动作、固定点击数、机器数、分库编号与目录数量作为通用质量指标。
- “412 项全部 mock Redis”：测试基座实际启动临时 Redis，部分测试验证受限 ACL。该临时实例关闭持久化，不能证明断电耐久性。

工作区 README 的轮次范围是 7～12，当前代码为 9～14；docs/ 与 tests/ 被 Git 忽略。其内容用摘要单独标识，不能把工作区文档或历史测试记录当作当前部署证据。来源文件及已知边界保留为案例，不以一次来源核对宣称线上问题已解决。

## 本轮评测与维护规则

维护者明确要求：技能评测必须做，但对模型使用不作要求。因此删除强制 Claude CLI、固定重复次数及强制模型新旧对照要求；场景评测、真实输出、判定标准和适用回归仍须完成。台账新增 `evaluated`，表示完成评测而不宣称相对旧版提高。
