## A：summary 比 button 矮，浅色页面普通条目变白

### 实际交付：一份共享控件契约与静态定位表

范围只含同一个 details 导航菜单的触发器、浮层和条目，以及会覆盖它们的页头/主题规则。保留既有菜单函数、导航目标和操作含义，不新增组件框架。

设计交接：触发器与旁边同级 button 使用同一高度、字体/行高、内边距、圆角、描边、图标基线与可见焦点。44px 可作为本场景已有 button 基线的对齐建议；它是建议的目标，不能说已经测得。沿既有 token 写入短契约，不另建全站 token 系统。浮层、普通项、当前项及 hover/focus 使用已声明组件样式；切换宿主不应意外改变普通条目。

候选 CSS 的静态定位：

| 输入声明 | 能支持的结论 | 仍需现场确认 |
| --- | --- | --- |
| `header button{min-height:44px}` | 只匹配 button，不匹配 summary | 邻近 button 实际尺寸；是否还有其他胜出规则 |
| `.switch summary{padding:6px;font-size:12px}` | summary 有独立文字与留白规则，没有该44px最小高度 | 实际行高、边框、box-sizing、浏览器默认布局；仅凭 CSS 不能计算最终高度 |
| `.switch button{background:transparent}` 后接 `.light button{background:white}` | 二者优先级均为 `(0,1,1)`；同一按钮同时匹配时，后置白底声明胜出 | 菜单条目是否确实位于 `.light` 后代、是否存在更高优先级或 important 声明 |
| `.switch button[aria-current]{background:green}` | 优先级 `(0,2,1)`，高于上述白底规则，可解释当前项仍绿 | DOM 是否只给当前项设置该属性；存在属性即匹配，不能把 `aria-current="false"` 自动理解成不匹配 |

如果浮层也位于 header 后代，`header button`还会影响内部条目；如果浮层挂载在别处则不匹配。应检查真实父子关系，不能仅凭触发器在页头就断言所有条目都命中。

### 可执行定位与修复交接

1. 在两个实际宿主的相同断点，记录 URL、实现版本和菜单当前项；确认 summary/button 标签及浮层挂载位置。
2. 对关闭的触发器、邻近同级 button、展开后的普通项与当前项，记录 bounding box 和相关 computed style：font、line-height、padding、min-height、border、radius、background、color、box-sizing；保留胜出声明及源码位置。
3. 用上述静态定位表逐条核对，不把“换了一页”当成根因。当前材料没有生产源码路径/版本，定位记录不能伪造 path:line。
4. 获授权修复时，补齐共享触发器基线，收窄穿透菜单的页头或浅色容器规则。保持已有 hover/current/focus，不逐宿主复制菜单，不叠加通用 important。

### 定向验收与证据边界

执行“宿主甲打开菜单→选择宿主乙→再次打开→返回甲”，同断点对照约定属性，完成一次安全且属于本次范围的导航/子项操作。若有受影响窄屏，再核菜单边界、可滚动区域和末项可达。主按钮允许的语义差异单列，不要求与所有次按钮同色。

本轮静态机制解释与给定症状相容；尚未拿到实际 DOM 和胜出声明，因此不是现场复现、不是修复确认。没有执行新的 UI 或全量测试。

## B：已批准明暗变体、绿色主按钮和红色危险按钮

### 实际交付：一份变体保留表与范围声明

“界面统一”在本轮落实为共享导航菜单的约定一致性。沿产品已批准的亮/暗控件变体，不重做方向选择，不改变正文主题，也不改动范围外主按钮或危险按钮。

| 对照条件 | 应保持 | 允许不同 |
| --- | --- | --- |
| 同一导航菜单、同一已批准变体、相同状态 | token/几何、文字基线、图标对齐、焦点与条目状态规则 | 文本长度引起的合理宽度变化 |
| 同一菜单的已批准亮/暗变体 | 导航目标、交互语义、可访问性及变体契约规定的共享属性 | 已批准的颜色、对比度及其他明确变体属性 |
| 主按钮/危险按钮与菜单触发器 | 各自既有语义和可辨识性 | 绿色主操作、红色危险操作；不因“统一”全部改成同色 |

把菜单使用的已批准变体明确映射到宿主，不把祖先选择器偶然造成的配色当成批准。若已有变体规格允许形状差异，也保留；不能凭本候选方法反向宣布所有几何都必须相同。

### 可执行定位与验收

1. 从当前已接受规格列出导航菜单的变体映射，核实际 DOM/token/class 是否表达该变体，而非任意祖先碰巧命中。
2. 在每个受影响宿主内对照“实际样式→该宿主应使用的批准变体”，不跨亮/暗截图直接断言色值相同。
3. 修复目标仅为违背变体契约的导航控件属性；检查 selector 收窄不会移除全局主次/危险变体。
4. 只在相关宿主执行关闭/展开、适用选中/hover/focus及一次子项导航。周边主/危险按钮做受影响样式观察，不执行危险写操作来凑覆盖。

没有执行渲染或变体对照；本案交付的是可实施对照条件。输入没有提供具体 token、色号或实测尺寸，不补造这些事实。

## C：两来源同样式，自动续载与手动加载不同

### 实际交付：一份视觉不变量与行为保留清单

范围是菜单触发器、面板、条目及状态的一致性，不包含业务加载策略调整。两来源的视觉复用不形成统一分页授权。

| 来源 | 本轮保留的行为 | 菜单修改不得产生的副作用 |
| --- | --- | --- |
| 自动续载来源 | 沿已有尾部触发、cursor、结束和失败显式重试行为 | 变成必须点击、重复注册 observer、重复追加或切换后迟到写入 |
| 手动加载来源 | 沿已有明确点击加载行为与剩余量表达 | 因共用容器而新增滚动/进入视口自动请求 |

本中立场景没有提供首批/追加量、模式重置数或计数单位，本轮不填入任何既往案例的数字。菜单修复可以继续；若实际改动触及加载消费者，再由对应实施者核对并登记这些数量，不把它们变成无关的前置调查门。

### 可执行定位与验收

1. 列出两个来源承载菜单的祖先和批准变体，定位导致菜单差异的 CSS；将菜单处理与列表 observer/click handler 分开核对。
2. 确认拟改规则的命中范围仅覆盖菜单/相关同级控件；不要顺手重写加载、授权、计数或提交函数。
3. 在来源甲实际打开菜单并到达目标，核自动续载仍沿既有触发方式；在来源乙确认仅滚到尾部不会触发手动加载，明确点击后才追加。
4. 读回当前查询的 total/已显示/剩余量及单位，检查菜单切换不导致重复续载或旧响应串入；失败恢复沿原契约，不因样式修复归零列表。

这是一份有界回归脚本，不是两来源运行结果。没有 UI、网络请求或加载计数的执行证据，不能声称业务行为已经保持，也不扩展成全库数据或全量测试。

## D：只有桌面截图与DOM通过，当前浏览器已被切到其他原型

### 实际交付：一份证据台账与待执行定向脚本

| 材料 | 当前能支持 | 当前不能支持 |
| --- | --- | --- |
| 单张桌面截图 | 该截图所示状态的可见呈现；版本/URL/日期未给时继续注明未知 | 当前运行页面、其他宿主、展开/hover/focus状态或窄屏表现 |
| DOM测试通过 | 该用例实际断言的结构/处理函数结果，报告其环境与替身范围 | 实际CSS级联、几何、指针点击链和浏览器视觉一致性 |
| 当前浏览器是另一原型 | 原定位与对象上下文已失效 | 把“没变化”、旧截图或旧定位当作新页面通过 |

本轮不操作浏览器，不接管另一任务、关闭其对话框或绕过宿主约束。可以继续完成候选规则对照、静态 CSS 检查、变体契约及定向脚本；实际页面验证明确标为待执行。

后续由有权操作者在浏览器可用时执行：

1. 重新确认实际 URL、构建版本、宿主、断点及当前页面身份；重新取得定位，不恢复盲点旧坐标。
2. 在受影响宿主取关闭/展开及适用状态的证据；跨宿主比较使用相同断点和明确变体条件。
3. 沿真实指针/键盘完成一条本次受影响的安全子项路径，记录目标内容、关闭与焦点结果。
4. 只有窄屏布局受影响时补该断点；回归限定于相关控件及消费者。不能因为拿不到浏览器而改跑全站/全量测试，并把后者当作视觉证据替代。

结果记为：文字契约/静态分析已完成，实际跨宿主视觉与点击路径未执行。现有截图和DOM结果按其原范围保留，不升级为本轮验收通过。若暂无操作者或可用页面，登记缺失证据与后续责任角色，不虚构具名负责人或完成时间。
