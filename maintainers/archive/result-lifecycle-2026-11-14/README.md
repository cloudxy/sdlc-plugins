# 异步成果与历史展示的方法反馈

本次按用户明确要求，将角色合成台维护中可复用的经验反馈到design-contract，而不是只留在产品私有计划。失败类型是conditional：不同用户任务/刷新基线下，当前结果和历史的恢复行为应不同；部分成功也应保留其真实阶段。

方法变更只在原Skill入口和既有局部重设计参考中增加生命周期责任，不新增agent、审批、持久账本或闸门。既有菜单、图库与配置方法保留。重点是当前草稿/提交快照/本次结果/历史分别有归属；刷新不自动继承最新历史；是否恢复依用户基线；转存/记录保存失败不默认再次生成；清空/复用/复制/保存的名字和成功依据一致。

来源：vsc-workflow原角色合成台，基线2eed477、刷新修复20847f8。源码两处历史→preview自动回填均被定位；新增反例在旧代码2项失败，修复后相关3个Node文件25项通过。Chrome原模块+隔离服务实际生成一次本地合成PNG（无供应商调用），刷新后结果位空、历史1条保留，详情打开/关闭。其他更大交互问题仍为已定位设计问题或提案，不声称全部已实施。没有向此仓库复制真实角色、图片、凭据或用户历史。
