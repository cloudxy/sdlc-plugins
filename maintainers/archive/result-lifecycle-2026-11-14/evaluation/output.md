# 五个局部设计场景：行为说明与验收操作

状态：设计建议 v1，待实现与验证；没有执行产品验收，也不构成设计批准。

## 范围、依据与交接

本轮采用 `reuse / local refinement`：沿用既有工具及输入给定的用户要求、已批准基线，修正结果归属、恢复、错误及动作语义。不新增方向竞选或批准周期，不推定五个工具必须采用相同刷新行为。输入未给出可核对的产品设计版本、组件、token 或运行页面；“已批准”仅指场景 B 的输入声明，未独立查验批准记录。

输入版本：本次读取的 `evaluation/input.md`，文件未声明版本号。输出版本：本文件的局部设计建议 v1，按 A—E 标识变更范围。交接前应由维护者补入真实需求、设计基线和实现版本，使下列复验能绑定到具体版本。

以下“当前”事实均来自输入描述，不是源码检查或运行观察。推荐行为是实施目标；验收步骤尚未执行。前端负责状态呈现与动作，架构负责确认身份、生命周期及恢复可行性，PM 处理业务行为变化，QA 按下列路径核验；真实用户或获授权的决定人负责接受，设计建议不替代其决定。

共同原则：当前输入草稿、提交时输入、执行请求、本次结果、历史记录分别归属；可见媒体应能追溯到相应提交或显式选择的历史。成功状态必须说明成功的是生成、媒体转存、历史保存还是剪贴板写入。复验要覆盖结果→历史→刷新或返回，并改变一次响应状态。权限未知、加载失败、离线和真正空集合分别表达。

## A：封面合成器

### 可观察问题与局部目标

输入描述中，两次加载都把历史第一条赋给结果区，因此刷新会自动显示旧封面，违背“刷新后右边空出来，但以前做的封面还能查”。没有独立结果身份还会使后台补读覆盖用户刚生成的封面或正在查看的历史。永久删除全部记录改变了历史数据，不能充当清空工作位的实现。

推荐将右侧定义为“本次工作位”，历史列表与单张详情继续承担“以前做的封面”。保留现有布局与历史查看入口；只调整状态归属和加载副作用。

### 推荐行为

| 事件 | 本次工作位 | 历史与输入 |
|---|---|---|
| 首次进入、浏览器刷新 | 无本次结果，不自动选历史第一张；可显示“本次还没有封面。合成后在此预览。” | 历史照常读取；已有记录不能被删除。输入草稿是否持久化沿原基线，输入未说明，不能连带清空 |
| 首批历史到达、后台补读完成 | 保持当前工作位及其结果身份 | 只更新历史集合，不触发本次成功状态 |
| 发起合成 | 结果区属于这次提交；若暂留旧封面，标为“上次结果” | 保存提交快照；后续草稿编辑不改这次提交 |
| 合成成功或失败 | 成功显示对应本次请求的封面；失败显示本次错误，不用历史第一条替代 | 历史保存成败另行表达；不能因加载/保存失败删掉已得结果 |
| 显式打开历史详情 | 查看所点记录，明确“历史封面”及该记录身份 | 详情关闭/返回后恢复打开前工作位、草稿；查看历史不隐式复用输入 |
| 同一页面内往返 | 推荐保留尚在会话中的本次工作；真正刷新仍回空位 | 不因打开/关闭详情重新自动选历史。跨路由保留能力须由前端确认 |

历史正常返回零条才显示“还没有保存的封面”；历史加载中显示“正在读取历史封面”，失败显示“历史封面读取失败，重试”，均不改变右侧空位或本次结果。离线时说明“历史封面暂时无法读取，联网后重试”；有合法可用缓存才允许显示并标识缓存。权限加载中不能当作无权限或无记录；真实权限拒绝时说明哪项不可用及既有求助入口，不编造权限申请功能。

“清空本次预览”若提供，只影响本次展示，不删历史；永久删除历史仍是独立破坏性动作，明确对象并确认。输入只证明有“永久删全部”接口，不能把它包装成单张删除或清空展示。未保存结果涉及唯一字节时，先提供可行的保留方式，不能以清空为由丢弃。

### 条件与未决能力

前端与架构需确定本次请求、其结果及历史记录各自可用的稳定身份，隔离晚到响应；这里是行为契约，不指定数据库字段或新增接口。历史详情现有能力可复用；跨路由恢复、未保存媒体导出和缓存权限规则尚未提供。PM/用户仅在要改变草稿恢复或删除语义时补决定，不必重新批准已明确的刷新空位要求。

### 验收操作与完成标准

1. 在受控测试数据中准备两条可辨认的历史，刷新：右侧不显示任一旧封面，历史仍可查；延迟后台补读后再次检查。核对未调用永久删除接口，历史数量不减少。
2. 打开第二条历史，检查详情媒体、标题及记录一致，关闭后工作位与草稿恢复；用键盘走完打开、内容操作和返回。
3. 生成一张新封面并延迟历史响应：本次结果不被覆盖。再模拟本次请求失败：错误归属本次，不把历史封面标为成功。
4. 从本次结果进入历史、返回、再刷新：前两步保留打开前工作，刷新后空位且历史仍在。分别模拟历史加载失败和正常零条，提示不得相同。

满足以上可观察结果才可判该范围通过；权限、离线和窄屏还需在真实适用状态中复验，当前没有通过证据。

## B：档案审阅器

### 可观察问题与局部目标

这是日常阅读工具，输入声明的批准基线要求刷新恢复选中文档和阅读位置。“统一体验”不足以改变它。清空选中项、历史资料和列表会破坏已接受的任务；文档加载失败显示“没有文档”则把读取失败伪装成空集合。

### 推荐行为

- 首次使用且确无资料时，显示“还没有可阅读的文档”及现有可执行入口。尚在读取列表或恢复文档时，分别显示“正在读取文档列表”“正在恢复上次阅读位置”。
- 刷新时恢复原选中文档及位置；列表/历史正常加载。恢复过程不先选另一篇，也不把临时未加载解释成空集合。文档成功加载到可定位状态后恢复位置，避免先跳文首再反复跳动。
- 选中文档读取失败时，保留选中身份及待恢复位置，显示“这份文档读取失败。重试后继续阅读。”重试针对同一文档，不重置整个阅读工作台。
- 显式选择另一篇文档或历史资料后，显示被选对象；从详情或相关页返回，按既有阅读基线恢复原位置。新选择与旧响应发生竞争时，旧响应不能把选中项改回去。
- 文档已删除、内容版本已改变导致位置无效、明确权限拒绝，均是有原因的恢复分支，不能统称“没有文档”。无法恢复位置时说明原因并提供“从文首阅读”或既有选择入口，不静默声称已恢复。
- 离线时保留可识别的选中项和阅读上下文；仅在确有合规缓存能力时继续展示缓存并标明，否则说明联网后重试。权限仍在查询时显示检查中；确认无权阅读后再按已有权限规则限制内容。

本地目标是恢复可预测性与错误反馈，未提出新视觉系统或删除资料动作。

### 条件与未决能力

前端/架构提供当前选中项、阅读位置已有保存方式及生效范围，确认文档更新后的定位策略、权限和缓存限制。输入没有这些实现证据，不能声称恢复已经可靠。PM 如坚持“刷新全部清空”，应先处理与已批准阅读目标的冲突；本轮继续按现有批准基线设计，不执行清空。

### 验收操作与完成标准

1. 打开指定文档，滚到可辨认的段落后刷新：仍选中该文档并回到该段落；历史及列表保留。测试长文档和加载延迟。
2. 令该文档加载失败：仍能识别原选择，出现针对同一篇的重试；恢复响应后回到原位置。再用真正零条列表，确认空态与失败态不同。
3. 快速切换两篇并让第一篇晚到：最终仍是用户后选的文档。选择历史资料、打开相关内容并返回，复核位置归属。
4. 分别模拟位置失效、权限查询中、权限拒绝和离线，核对提示及恢复入口；未提供的缓存能力不能在验收记录中写成可用。

完成标准是批准的恢复行为保留、失败不冒充空态；没有运行证据之前只可记“待验证”。

## C：配音转换

### 可观察问题与局部目标

任务12转换已产出本地临时音频，失败发生在保存历史。任务11的播放器与“已完成”绿勾却占据结果区，小通知只说“请求失败”，用户无法判断哪一步成功、哪一份音频可用，可能再次付费转换。任务12供应商回执已经固定，应先恢复它的成果，而不是新发生成请求。

### 推荐行为

当前结果明确关联任务12及其提交输入，显示“任务12：转换已完成，历史记录未保存”。播放器若能读取任务12临时音频，播放对象必须为任务12；若当前前端还不能读取，应显示“音频已生成，预览暂不可用”，同时保留文件及回执，不用任务11的播放器替代。任务11如继续展示，进入独立的“上次结果：任务11”区域，播放与状态均不冒充任务12。

分开表达至少三类状态：尚未收到转换结果；转换有结果但媒体转存失败；媒体已转到本地但历史记录未保存。本例属于第三类。历史保存错误要常驻在任务12附近：“音频已生成，但历史记录保存失败。先保留音频，再恢复保存。”不能仅靠短暂小通知，也不能用一个覆盖全部阶段的“已完成”。

保存恢复只针对既有任务12、其音频和固定回执。后端已知只有新转换和任务查询，不能呈现一个实际上调用“开始新转换”的“重试保存”按钮。推荐的恢复顺序：

1. 保留现有临时文件、任务身份、提交快照和回执，不因新一轮、清空显示或保存失败自动清理唯一成果。
2. 若前端已能导出这份临时音频，提供“下载任务12音频”，只下载既有字节；下载可用性由前端确认，当前不能宣称已具备。回执与任务查询能力不等于可以重新取回媒体。
3. “重试保存历史”属于待确认/待实现的能力：若能用现有文件及回执重新写浏览器存储，可实现为仅保存，不调用供应商、不新增转换；重复点击不能产生重复历史。后端没有重试保存接口不自动证明前端一定不能恢复，但也不能假定前端已有该能力。
4. 当前已知可查询任务12，可用于核对转换状态；查询不标作历史保存成功。仅保存失败或提交状态不明，都不默认再次转换。用户确要新转换时走独立入口，明确可能产生新的用量。

刷新/离开之前应说明“历史尚未保存。临时音频的刷新后恢复能力未确认，请先保留可用文件。”是否能提示、导出和拦截离开需前端确认。不能承诺临时文件永久存在，不能为刷新清空工作位而删除它。刷新后只在能准确找回任务12与媒体时恢复对应结果；若只能查询回执，就说明媒体恢复仍不可用，不能从最新历史回填任务11冒充恢复成功。

### 条件与未决能力

架构/前端确认临时文件可读范围、清理时机、任务身份在刷新后如何找回、浏览器存储失败原因及是否有不重新转换的保存路径。若需要新的媒体恢复或保存接口，交架构评估；PM 确认恢复能力的交付范围及再次转换的业务提示。没有授权改变供应商回执或重新计费。历史权限未知、离线、存储容量边界需单独说明；没有具体容量数据，不设虚构上限。

### 验收操作与完成标准

1. 用替身任务11、12的明显不同音频，令任务12转换/转存成功、历史写入失败：核对可见任务身份、实际播放内容、分阶段状态及常驻恢复说明。
2. 检查失败期间文件与回执仍可用；如实现导出，核对导出的是任务12原音频。缺导出能力时如实记录缺口，不能只验按钮出现。
3. 如实现仅保存重试，使首次存储失败、随后成功：确认沿用任务12和原回执，重复操作不重复建历史，且“开始新转换”调用次数不增加。存储持续失败时仍保留媒体。
4. 模拟查询失败、离线及刷新：分别检查无法确认状态、保存失败、媒体不可恢复的文案；旧播放器不能重新被标作任务12成功。验证临时文件失效后的真实恢复能力。

当前可确定的设计完成标准是归属清楚、部分成功不被抹去、恢复不重发付费转换；恢复接口和文件持久性未验证，不能记录保存恢复已通过。

## D：海报批处理

### 可观察问题与局部目标

已提交的是标题A、参考1、模型X，执行中输入改为标题B、参考2。旧响应配上当前标题B造成结果归属错误。用户有明确的下一轮准备需求，不能通过锁住全部输入解决。“恢复原设置”实际只恢复提示词，动作范围也不真实。

### 推荐行为

- 点击执行时冻结一份完整提交快照，包含实际提交的标题A、参考1、模型X及该次提示词等参与执行的输入。正在执行的请求和结果使用这份快照；草稿B/参考2属于下一轮。
- 执行中仍可编辑草稿，输入附近显示“更改用于下次执行”；本次进度标注“正在处理标题A”。完成通知与结果标题仍为A，参考及模型信息仍为1/X，不能从当前表单重新取标签。
- 若后端尚未证明支持并行批次，执行期间只限制重复执行该请求，保留所有可准备下一轮的输入；不以此新增并行能力。失败只更新该次执行状态，不抹掉B草稿。
- 新一轮开始后，上轮结果可继续保留，但标为“上次结果”并保有独立身份；延迟的旧响应只更新所属任务，不能覆盖新一轮的结果或状态。查看历史与返回也不覆盖待执行草稿。
- 对现有只恢复提示词的动作，最小局部修正是命名为“复用提示词”：明确仅替换草稿提示词，标题B、参考2、模型选择、当前/历史结果均保持；有未提交提示词将被替换时，说明覆盖范围并允许取消。完成反馈为“已复用提示词”。
- 如果真实已接受需求是完整恢复，则应改为“复用本次输入”，并恢复整份提交快照；需补齐标题、参考、模型、参数等可用性及覆盖契约。缺失或已不可访问的参考不得静默省略后宣称“已恢复原设置”。输入未提供该批准要求及能力，本轮不把完整恢复当成现成能力。

首次进入/刷新采用该工具原有基线，输入未说明，不能套用A的清空或B的恢复。若原有基线允许恢复结果，恢复的是对应提交快照；无法确认快照时标明缺失，而不是配上当前草稿。真实空历史、读取中、失败、权限和离线分别保留其语义；草稿能否离线编辑、参考能否离线恢复需要技术确认。

### 条件与未决能力

前端/架构确认提交快照是否包含全部有效输入、可关联请求身份、批次中多张海报的归属及旧响应隔离方式；确认参考1之后不可访问时的展示/复用降级。PM 只需处理“仅复用提示词”是否与既有已接受的完整恢复需求冲突，以及未知并行能力和刷新基线，不需要重新选择视觉方向。

### 验收操作与完成标准

1. 提交A/参考1/X，等待时改为B/参考2并调整可编辑参数：输入可继续准备，进度、结果、下载/历史详情仍全部归于原提交。
2. 让A成功及失败各一次：B草稿均保留；失败不把上一张海报当成本次成功。若有新旧并发响应能力，再交换响应顺序，核对结果与状态不串批次。
3. 在B草稿上选择“复用提示词”，先取消再确认：只提示词变化，其他输入及结果保持；按钮与反馈不声称完整恢复。若选择交付完整复用，另测参考失效与缺失参数，不能用部分恢复记全量成功。
4. 本次结果→历史详情→返回→刷新，按经确认的刷新基线核对输入、快照与结果对应关系；刷新基线尚未提供时该项留为待验证。

完成标准是草稿可编辑、结果始终对应提交快照、复用命名与作用一致。当前没有实际运行或快照完整性的证据。

## E：动作与窄屏

### 可观察问题与局部目标

“清空”没有说明只清参考图，保留的提示词与上次错误容易被误解。剪贴板 API 不存在时可选链会跳过写入，现有逻辑仍报成功；拒绝或写入失败也不能当作成功。输入只提供1440px短文案截图，不能支持375px、键盘、失败恢复乃至“所有交互通过”。

### 推荐行为

| 动作/状态 | 局部行为与反馈 |
|---|---|
| 清除参考图 | 现有动作改为“清除参考图”，明确只移除当前草稿参考；手写提示词、结果及历史保持。无参考时禁用并给可感知说明“尚未添加参考图” |
| 上次错误 | 按原请求标为“上次执行失败”，不能作为当前草稿仍错误的证据。若是已被解决的输入校验，应依有效校验更新；输入未说明错误类型，实施前分类，不盲目保留或全部删掉 |
| 全部重置 | 本轮未要求增加；若产品确有该目标，先定义清哪些输入、是否涉及结果及错误、能否恢复，不能继续用含糊“清空”承担不同作用 |
| 复制成功 | 确认剪贴板写入能力存在，且写入实际成功后才提示“已复制提示词”（或对应的具体文本对象） |
| API 不可用/写入拒绝或失败 | 提示“未能复制。请选择文本手动复制。”保留可选择的完整文本；不显示成功，不自动发起不明权限操作 |
| 正在复制/无文本 | 写入等待时显示进行中并防重复反馈；无可复制文本时禁用并说明原因。长文本不能静默截断；具体长度限制须由能力方提供 |

复制提示作为可被辅助技术感知的状态反馈，不抢走当前编辑焦点。清除后焦点保留在可操作的合理位置；不全局移除焦点样式。若错误属于旧执行，输入变化不把它改写成当前执行成功。

375px采用既有组件与token进行局部适配：长按钮标签、错误说明和恢复动作可换行且可完整到达；主动作、参考移除、复制、结果和返回不能因卡片挤压或固定浮条被遮住。触摸目标至少44×44px；焦点顺序按输入、参考操作、执行及结果操作的实际任务顺序明确。只有真实存在菜单/浮层时才补测其内容操作、Escape、外部点击及关闭后的焦点，不虚构已存在控件。状态使用文字与适当图标，不只靠红绿；沿既有语义token，新增值及对比度必须在真实组件上核对。

### 条件与未决能力

前端明确清除动作涉及的字段、错误来源、复制对象、剪贴板返回及可选文本呈现方式；设计/前端给出适配后的375px长内容页面或原型，再由QA在运行页面验证。输入没有现有token、DOM、键盘顺序或失败反馈实现，不能声称对比度、焦点、触摸尺寸和读屏均已合格。

### 验收操作与完成标准

1. 放入参考、手写提示词、上次错误和结果，执行“清除参考图”：逐项比对作用范围，确认提示词/结果/历史未被误改；错误展示与其真实来源一致。无参考时检查禁用及说明。
2. 分别用可用且成功、API 缺失、写入拒绝、异步写入失败和延迟完成的受控条件操作复制；核对完整文本、成功提示时点和手动复制恢复入口。未经成功写入，不能出现“已复制”。
3. 在375px真实页面使用长提示词、长错误、完整按钮文案及实际结果，走到复制、清除、执行、恢复与返回的真实结果，截图并检查遮挡、横向溢出和可达性；同时复核1440px长文案状态，不能以现有短文案截图替代。
4. 用键盘Tab/Shift+Tab到达全部受影响控件，以Enter/Space执行适用动作，检查可见焦点、顺序及关闭/返回后的落点；有浮层再测其实际关闭路径。读屏、放大或减少动效未测的部分分别记为未验证。

验收记录当前只能写：“输入描述提供1440px短文案截图；本轮未独立查看截图，375px、键盘与复制失败路径均未验证。”开发提出的“所有交互通过”没有依据，不能采用。未来只能按执行过的版本、视口、输入方式和状态逐项给结论。
