# README 整理的场景评测

日期：2026-11-10。范围：9 份受版本控制的 README 类文件；下载的 vendor 原件、生成角色和 SKILL.md 未修改。

## 方法与预设判定标准

主会话根据改后文档执行有界任务情景，下面保存每个输入、实际回答与判定。评测对象是文档使用时的路径选择、归属和证据边界，不是完整交付技能的端到端表现。由同一主会话产生并核对回答，未使用独立评审、另一次模型调用或新旧对照；不据此推断质量提升。脚本与来源核对另行记录，不能代替这些情景回答。

在作答前确定以下标准：

1. 找到正确的源文件与生成命令，不建议直接改生成角色。
2. 能从 M 档索引区分本地验证、发布准备和实际发布；局部诊断不扩成全流程。
3. 使用产品 README 模板时保持文件归属、已有内容和未填标记语义，不把目录存在当作完成。
4. 能从回归索引选择正确案例，并识别缺历史输入、未运行与未做对照的限制。

## S1：角色维护

输入：只修改 backend 的表达风格，要让五端加载同一份变化；是否直接编辑 agents/backend.md？

实际回答：编辑 agent-sources/profiles/backend/SOUL.md。职责边界仍在 IDENTITY.md，专业步骤仍在任务技能。运行 `python3 scripts/render-role-agents.py`，然后 `--check`，使通用 Markdown、Codex TOML 和 Kimi Markdown 一起更新。生成角色不手改；若未改注册表或宿主清单，不需要为风格改动改它们。

判定：通过。输入限定风格，回答保持 SOUL 边界并找到生成器。来源：agent-sources/profiles/README.md；生成器源码与 `--check` 另行核对通过。

## S2：M 档交付准备

输入：L2 UI 功能已经完成本地验收，用户只要发布准备，不授权上线。最终原型、联调证据与准备结果分别去哪？

实际回答：最终原型在 `02-shape/prototypes/final/`，切片联调记录在 `03-impl/T-<n>-integration.md`，包含真实后端联调与截图。SRE 准备结果在 `06-deliver/readiness.md`，QC 意见在 `release-opinion.md`。目录索引不等于任务完成；执行发布仍需要授权，不把准备材料当作部署结果。

判定：通过。原型、联调、准备和实际发布含义可区分。来源：M 档 README 与根 README；SRE prepare 合同查询实际返回 readiness 路径。

## S3：局部诊断

输入：只定位漏采原因，暂不修复；看到 M 档的 00–07 目录，是否需要先补全设计、实现和发布文件？

实际回答：按已选诊断任务及完成目标取合同和证据要求，不因索引列出了完整阶段就补造产物。局部工作的版本、完成记录按持续工作协议查找；未执行的实现与发布不能记完成。

判定：通过。未把完整目录误读为每次必跑的任务清单。来源：M 档 README 的用途说明与“数据任务与局部工作”。

## S4：已有产品层的模板使用

输入：已有 strategy.md，只有 data/tracking-plan.yaml 缺失；PM 提出一个新事件。能否把整套模板覆盖过去，再由 PM 直接写数据字典？

实际回答：保留已有 strategy.md，只补缺文件。PM 通过 tracking.md 提事件，data-collector 负责 tracking-plan.yaml；任务派单可以进一步缩小写入范围。模板占位符表示未填，只有填入真实产品内容后才移除标记；推断内容标注并列为待确认项。README 与 CHANGELOG 由经理维护。

判定：通过。模板清楚区分初始化与覆盖、提案与写入归属。来源：product-readme.md 与现行产品层协议。

## S5：历史架构回归与输入缺失

输入：想评估缺最终设计时的架构行为；没有 auto_agents 的相关 Git 历史，能否直接用当前工作树宣布 R3 通过？

实际回答：选择 R3-agents-market-architecture，读取案例 JSON；缺最终设计的依赖项保持待完成。准备历史输入需要包含 artifacts_ref 和基线的仓库，当前工作树不能替代。没有准备并运行的案例记未验证，不能宣布 PASS。

判定：通过。索引能指向正确案例，并保留历史隔离与结果限制。

## S6：没有旧版对照的技能评测

输入：已经完成适当的技能场景评测并保存输出、标准与结果，但没有旧客户端和旧版对照，应该写什么结论？

实际回答：客户端不构成固定要求，实际完成的评测可记 evaluated。不能因没有旧客户端省略评测，也不能因单版本评测通过宣称比旧版更好；未运行的历史回归仍列未验证。

判定：通过。符合当前维护者指令。来源：回归 README、维护者 README 与 out-of-scope/2026-11-10-不限定技能评测模型与客户端.md。
