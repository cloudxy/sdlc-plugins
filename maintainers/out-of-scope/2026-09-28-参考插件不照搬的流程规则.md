# 参考插件不照搬的流程规则

- **结论**：下列来自 Superpowers 与 Matt Pocock 技能集的规则，不进入 SDLC 的方法文本。
- **来源**：维护者归档 `2026-09-29-SDLC流程升级-执行记录/2026-09-28-SDLC流程升级方案-Superpowers与MattPocock对照诊断.md` §12.3。该轮逐个评估了两边全部 53 个技能入口。

| # | 不照搬的规则 | 理由 |
|---|---|---|
| 1 | 所有任务都重新访谈、固定数量方案、固定次数人工批准 | 会把已授权的局部工作变成反复确认 |
| 2 | 只因技能适用概率很小就加载整个流程，扩大本次任务 | 扩大范围，违背按任务选择方法 |
| 3 | 原型一律转正式实现，或因原型没有生产级测试就否定探索结论 | 探索与交付的完成标准不同 |
| 4 | 无论规模都生成完整实现代码计划，或无论风险都只做一次最终审查 | 计划深度与审查强度应随风险变化 |
| 5 | 到返工上限自动把真实重大问题变成通过 | 阻断义务不能被次数豁免 |
| 6 | 只要 Git 无冲突就认定多项工作可以安全合入 | 集成正确性需要候选版本上的验证 |
| 7 | 用任务状态、Issue 关闭、测试退出码或代理自述替代相应业务证据 | 证据必须对应所声称的结果 |
| 8 | 以风格为名删除现有有效测试，或在普通修复中强制大规模架构重构 | 破坏回归保护，扩大范围 |
| 9 | 用平台特定命令、固定上下文窗口数字或模型档位作为跨宿主硬规则 | 五个宿主的能力不同 |

**什么会让我们重新考虑某一条**：对应场景下，按该条规则运行的对照评测在正确性指标上优于现行做法，指标包括遗漏验收、错误完成声明、逃逸缺陷；同时用户打断与重复工作不增加。只引用上游的说法不够。
