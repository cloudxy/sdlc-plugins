# Working on sdlc-workflow itself

For sessions that edit this plugin. Projects that use the plugin load its skills, commands and agents, not this file.

- Start at [maintainers/README.md](maintainers/README.md): the method baseline, gate catalog, and review cadence. Private maintainer notes, archives, rejection records and per-change logs live in gitignored local directories (`maintainers/private/`, `maintainers/archive/`, `maintainers/out-of-scope/`, `maintainers/method-changes/`) and must not be committed to the public repository.
- **Targeted testing only — full-suite test runs are forbidden.** Only run checks and tests for the affected parts; never loop over every `tests/test_*.py` or run unrelated test suites, as full-suite runs waste time. Run `bash scripts/health-check.sh` when structure, skills, agents, registry, adapters or the method ledger change, plus ONLY the specific `python3 tests/test_<affected>.py` matching the modified module (run `bash tests/test-check-sdlc.sh` — and `LC_ALL=zh_CN.UTF-8 /bin/bash tests/test-check-sdlc.sh` — only when modifying `scripts/check-sdlc.sh` or its gate helpers). Method text changes also need a local ledger record (updating `maintainers/method-baseline.json`). Skill changes require scenario-based evaluation as well as applicable targeted regression checks. No model, client, call count or model comparison is prescribed. Record the actual evaluation, criteria, results and limits locally; unavailable clients do not waive skill evaluation.
