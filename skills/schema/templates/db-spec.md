## 2.1 状态流转（有 status 字段的表必填）

```
<table>.status 合法流转：

pending ──支付成功──> paid ──发货──> shipped ──签收──> completed
   │                    │
   └──超时/用户取消──> canceled <──退款──┘

终态：completed, canceled（不可再流转）
```

| 流转 | 触发条件 | 谁能触发 | 副作用 |
|---|---|---|---|
| pending → paid | 支付回调成功 | 系统 | 扣库存、记 `paid_at` |
| pending → canceled | 超时 30min 或用户主动 | 系统/用户 | 释放库存 |

**非法流转**（`/qa` 要覆盖的负向用例）：`shipped → pending`、`canceled → paid`、终态 → 任何状态。

## 2.3 软删决策

| 表 | 加软删 | 理由 |
|---|---|---|
| `orders` | 是 | 业务需要恢复误删订单 |
| `order_audit_log` | 否 | 审计表按豁免矩阵不加 |

豁免矩阵：审计表 / 历史表 / 子表 / 聚合表 / 系统表**不加**软删。

加了软删的表,唯一键必须带上删除标记（否则删除后无法重建同名记录）：
`UNIQUE (tenant_id, order_no, deleted_at)` 或用 `deleted_at IS NULL` 的部分索引（PG）/ 应用层保证（MySQL）。
