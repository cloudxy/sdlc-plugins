# 领域建模：先有业务模型，再有表

按功能里出现的名词建表，第一个功能没问题，第五个功能开始出现：同一概念三张表、两个地方都在写同一个事实、每加一种类型就加一批列。领域模型是**全产品共享**的业务骨架，表结构只是它的一种落地。

## 1. 限界上下文：先切业务边界

限界上下文 = 一组业务能力 + 一套自洽的术语 + 一个明确的数据所有者。

识别方法（按顺序试）：
1. **语言分歧**：同一个词在两个地方意思不同（「订单」在交易里是一次购买，在履约里是一个配送任务）→ 两个上下文。
2. **变化节奏**：内容审核规则每周变，计费规则每季度变 → 分开。
3. **团队与负责人**：由不同人负责的能力，边界最好也分开。
4. **生命周期**：「数据集」的导入—清洗—版本 与「报表」的定义—发布—分享 各自完整 → 分开。

上下文之间的关系要写明：

| 关系 | 含义 | 数据上怎么落 |
|---|---|---|
| 上游 / 下游 | 下游依赖上游的模型 | 下游只存上游 id（引用），经接口读 |
| 防腐层 | 下游不想被上游模型污染 | 翻译成自己的术语后再存 |
| 共享内核 | 两个上下文共同维护一小块模型 | 极少用；必须有共同负责人 |
| 发布语言 / 事件 | 通过事件同步 | 事件契约 + 幂等消费 |

## 2. 聚合与不变量

聚合 = 一组必须**一起保持一致**的对象，有一个根；外部只能通过根修改它。

| 判断 | 问题 |
|---|---|
| 是否同一聚合 | 这两个对象之间有没有「必须在同一事务里始终成立」的规则？有 → 同一聚合 |
| 聚合多大 | 越小越好：并发冲突少、加载快。能用「最终一致」接受的规则就不放进同一聚合 |
| 跨聚合引用 | 只存对方的 id，不存对象；跨聚合的一致性用事件或定时对账 |

不变量写成一句可检验的话，并决定**由谁保证**：

| 不变量 | 保证方式 |
|---|---|
| 同一租户内报表名唯一 | 唯一约束 `(tenant_id, name)` |
| 订单金额 = 明细金额之和 | 同一事务内计算写入 + 对账任务 |
| 已发布的报表不能删除，只能归档 | 应用层状态机 + 非法流转测试 |
| 一个数据集最多被 50 份报表引用 | 应用层校验（计数 + 行锁或乐观锁） |

## 3. 轻量事件风暴（30–60 分钟，单人也能做）

1. 沿关键旅程写出**领域事件**（过去式）：`数据集已导入`、`报表已生成`、`报表已分享`、`分享链接已撤销`。
2. 在每个事件前写**命令**（谁触发）：`导入数据集`（租户管理员）。
3. 找出每个命令改变的**聚合**：`导入数据集` → Dataset。
4. 标出**规则 / 不变量**（在命令执行前必须检查的条件）。
5. 圈出聚合与上下文边界。

产出直接写进 `domain-model.md` §1–§3；事件名同时成为 `tracking-plan.yaml` 与事件契约的候选（统一语言）。

## 4. 从现有系统反推（棕地产品）

| 证据 | 能反推出什么 |
|---|---|
| 迁移文件历史 | 概念出现的顺序、被改过几次（改得多 = 边界不稳） |
| ORM 模型与外键 | 实体、关系、隐含的聚合 |
| 服务目录 / 模块划分 | 现有的上下文边界（可能是错的，标出来） |
| 唯一约束与校验代码 | 不变量 |
| 同义表 / 同义列（`customer` vs `user` vs `buyer`） | 统一语言缺失的地方 |
| `type` 列 + 大量可空列 | 没被显式建模的扩展点 |

推断出来的内容标 `[推断]`，并作为 pm / architect 的待确认项。

## 5. 功能级增量怎么做

1. 找到本功能所属上下文；如果需要新上下文，写明为什么不属于现有上下文。
2. 新术语先进词汇表，检查是否与已有术语冲突。
3. 写新聚合 / 新不变量 / 触及的扩展点。
4. 记录**被否决的建模方案**及理由（最常见的是「直接在现有大表加列」）。
5. 做路线压力测试（SKILL Stage 8），不通过就回到第 3 步。
6. 评审通过后回写 `domain-model.md` 与 `erd.dbml`，在演进记录加一行。

## 6. 反模式

| 反模式 | 症状 | 修正 |
|---|---|---|
| 以界面建模 | 一个页面一张表，页面改版就迁移 | 以业务概念与不变量建模 |
| 上帝表 | 一张表 60 列，大部分可空，按 `type` 分用途 | 拆聚合或用扩展模式 |
| 双写 | 两个模块都写同一个事实 | 指定唯一所有者，另一方读或订阅事件 |
| 语言漂移 | 表叫 `projects`、接口叫 `workspace`、界面叫「空间」 | 统一语言，一处定义 |
| 巨型聚合 | 为了「一致」把整个租户的数据放在一个事务里 | 缩小聚合，跨聚合最终一致 |
