# 可恢复写入、发布与确认

适用于多步持久状态转换、跨存储交接或提交确认可能丢失的路径。先核对引擎版本、实际 ACL、并发与持久化配置；能在现有事务存储内满足要求时，比较它与自建恢复协议的成本。禁止 Lua 不意味着必须增加一套 journal，也不能推断普通命令全部可用。

## 保证范围

| 机制 | 可提供的保证 | 仍需解决 |
|---|---|---|
| 单条最终值写入 | 在该命令边界替换一个值 | 读改写竞争、回复丢失、服务器持久性 |
| 最终值计划＋重放 | 在限定写入/读取协议下，中断后可完成转换 | 中间态可见性、竞争写者、计划丢失、全量重写成本 |
| 临时数据校验＋原子替换 | 该替换边界内不暴露逐条写入的半成品 | 多结果整体可见性、空结果表达、消费者提交 |
| 引擎事务 | 所选引擎/配置实际支持的事务边界 | 隔离、运行时错误语义、提交未知和外部副作用 |

同库或同服务器能简化协调，不自动产生事务；进程内锁只约束该进程。单键原子发布不等于整个任务、多个数据类型或下游落库原子完成。

## 最终值计划的适用前提

如果选择可重放写入，在数据设计或 ADR 中声明：

- **所有权与读路径**：谁能写每个目标及计划键，如何发现重复进程；恢复与正常读写如何串行。相关读者在使用状态前恢复或通过版本/可见性协议读取，直接读原始键可能观察中间态。多个写者需另设引擎约束、条件写或可执行的版本/隔离协议；仅写一句“单写”不是运行保障。
- **计划与重放**：先确认保存不可变计划，再执行目标写入，全部确认后清计划；计划标识、结构版本和目标范围可校验。最终值可保留合法重复业务行；传输重放去重不等于按内容删业务行。损坏或类型冲突时保留计划与现场，进入修复路径，不能靠删除计划假装成功。
- **时间与事件**：暂停等截止时间随计划保存，恢复时计算剩余时间，不重新从当前时间延长。说明时区、时钟偏差与到期边界。一次状态转换可重放，不代表多个失败事件已被去重；需要时另设稳定事件身份。
- **耐久性与代价**：核对持久化、故障恢复、淘汰及外部清理策略；`SET` 成功、无 TTL 都不能单独证明断电不丢。最终值若包含累计 List，估算每次全量读取、计划大小、重写流量及恢复时间，再决定是否改用分块或其他存储。

## 发布确认未知

使用 staging 时明确准备、发布意图、发布、确认各状态。意图保存前可按协议重建暂存；意图确认后保持其内容与身份，避免回复丢失后重新生成另一份发布。

“暂存键消失，说明 RENAME 成功”仅在该键不会过期、被逐出、被外部删除或丢失，且目标有受控写者等假设成立时有效。缺失原因不明应保留未知状态并对账。正式数据已被消费者取走，也不能据缺失自动重新发布。Redis Cluster 等拓扑还需核对命令、键位置和权限限制。

合法空结果必须有消费者认可的完成表达（如 manifest 或明确的空批次），不能用“没有 List 键”同时表示空结果和未采集。业务要求多个结果一起可见时，可评估版本 manifest/指针等提交边界；允许逐项交付时保留相应契约，不强制增加整体事务。

## 至少一次交接

1. 同一事件重传沿用稳定 ID 和内容；相同 ID 对应不同内容进入冲突处理。内容摘要可核对一致性，不能把两个内容相同的独立事件合并。
2. 接收确认必须标明边界：入队、持久接管或业务提交。先写回执再做副作用，可能留下“已确认但从未执行”；先做副作用再写回执则有重复窗口，应靠恢复与消费者幂等处理，不能宣称恰好一次。
3. 消费者把去重记录和业务变化放在可用的同一事务或等效恢复协议中，提交后才确认/清理输入；事务外副作用另有幂等与恢复义务。生产者确认状态持久化后，失败的本地清理只续清理。
4. 去重记录覆盖允许的离线、重试、人工重放窗口；超窗行为明确。消费者提前清回执可能让未收到确认的生产者再次投递，因此消费者持久幂等的保留范围也要匹配。
5. 只清理对应已确认记录；软容量阈值暂停新增并让补传/清理继续，硬上限保留未确认数据并报告处理路径。旧格式迁移若要丢弃未确认记录，需要该项目明确的数据处置授权，不能推广为通用清理规则。

SQLite 与同盘 JSONL 可以互相辅助恢复，不构成跨设备备份。非关键诊断可降级；如果审计是业务准入条件，则由契约决定写入失败影响哪些操作。

## 按风险选取的故障验证

| 注入点 | 核对不变量 |
|---|---|
| 每个关键写入前后中断、操作成功但回复丢失 | 可恢复；原任务/事件身份不变；已发生副作用能被识别 |
| 发布后下游已消费、回执缺失或超保留期 | 不凭正式键缺失推断从未投递；按契约处理重复与未知 |
| 重复进程、未经过恢复的读者 | 排他机制真实生效，或明确检测/拒绝；验证实际可见状态 |
| 暂存/计划被逐出、损坏、权限拒绝 | 不误报完成；保留可恢复材料并触发对应处理 |
| 合法空结果、同内容不同事件、缺少必需单元 | 空结果可交付；独立事件保留；缺失不冒充成功 |
| 容量恢复、独立健康依赖 | 补传能够排空，准入可恢复；停止范围不扩大到无关任务 |

记录输入、环境/ACL/持久化差异、代码版本、原始结果与未验证边界。临时真 Redis 可验证命令及权限语义，关闭持久化的测试实例不能证明服务器崩溃耐久性；mock、模拟与真实下游验证分别陈述。
