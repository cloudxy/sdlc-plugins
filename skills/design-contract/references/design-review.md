# 设计走查（design QA）：拿运行中的构建和选定原型并排比

阶段 `accept`，task `design-qa`。目的：在上线前拦住「实现和设计越走越远」——间距、层级、状态、文案、动效和签名时刻，只要没人对照，就会在开发中慢慢丢失。

## 准备

| 输入 | 用途 |
|---|---|
| `02-shape/design-directions.md`（选定方向）与 `02-shape/prototypes/` 截图 | 对照基准 |
| `02-shape/flows.md` · `02-shape/edge-states.md` | 交互与状态基准 |
| 产品 `design-system.md` | 原则、tokens、签名时刻 |
| `03-impl/*integration*.md` 与 E2E 截图 | 已有实现证据 |
| 运行中的构建（`app.base_url`） | 亲自截图 |

## 步骤

1. **同条件截图**：用与原型相同的页面、数据状态和断点截图：
   `bash PLUGIN_ROOT/scripts/ui-evidence.sh <url> <feature>/04-verify/shots/design 375,1440`
   然后逐张打开 PNG，与原型截图并排看。
2. **五层检查**（由粗到细，粗层有问题先不看细层）：

| 层 | 看什么 | 典型问题 |
|---|---|---|
| ① 结构与层级 | 信息架构、主次、视线路径、首屏要素 | 主操作被挤到折叠下；次要信息抢了视觉重心 |
| ② 签名时刻 | 选定方向的那一刻是否存在、时机与动效是否对 | 渐显动效被砍、结果出现后没有焦点引导 |
| ③ 状态 | 空 / 加载 / 错误 / 边界 / 权限 / 离线 | 空态是「暂无数据」；错误只有 toast 没有下一步 |
| ④ 视觉规格 | 间距节奏、字号层级、颜色语义、圆角阴影、断点布局 | 硬编码颜色；移动端两栏挤压 |
| ⑤ 文案与可访问性 | 文案与 edge-states 一致；对比度；焦点可见；键盘可达；减少动效 | 按钮文案变成「确定」；focus 环被去掉 |

3. **记录差距**，每条附两张截图（原型 vs 构建）。

## 严重度

| 严重度 | 定义 | 例 |
|---|---|---|
| 阻塞 | 签名时刻缺失，或任一关键旅程步骤的结构与设计相悖，或可访问性底线不达标 | Aha 时刻没有任何视觉反馈；对比度 2.1:1 |
| 主要 | 状态缺失、主次颠倒、文案误导 | 权限态显示空白页 |
| 次要 | 规格偏差但不影响理解与操作 | 间距 12px 应为 16px |
| 瑕疵 | 像素级 | 图标 1px 偏移 |

## 结论规则

| 结论 | 条件 |
|---|---|
| `结论：通过` | 无阻塞、无主要差距；签名时刻存在且表现正确 |
| `结论：有条件通过` | 无阻塞；主要差距 ≤2 且有修复负责人与期限（需用户接受） |
| `结论：不通过` | 任一阻塞，或主要差距 >2 |

结论行原样写成 `结论：通过` / `结论：有条件通过` / `结论：不通过`（闸门据此判定）。

## 差距去向

| 性质 | 去向 |
|---|---|
| 实现偏离契约 | frontend 返工（附截图对比） |
| 契约本身有缺（设计漏了某个状态） | designer 补 edge-states → 标 stale → frontend 实现 |
| 技术限制导致无法实现 | architect 确认 → designer 给降级方案并更新契约 |

## 回写

`design-system.md` 的签名时刻清单：更新状态（已实现 · 走查通过 <日期> / 降级为 … / 撤回）。新增的可复用模式补进模式清单。
