# 设计探索：发散出真正不同的方向，再收敛出有记忆点的那一个

task `explore`。目标不是「画一个看起来专业的页面」，而是**给人选择**：几条真正不同的路，每条路的记忆点、代价和风险都摆在桌面上。

## 1. 先定三件事再动手

| 问题 | 来源 | 影响 |
|---|---|---|
| 这是什么类型的界面？ | spec 旅程 + `design-system.md` 界面类型表 | 高频工作台求一致与效率；首次体验 / Aha 路径求记忆点；对外页求传播 |
| 用户在这一刻的情绪是什么？ | 旅程表「用户想什么 / 情绪」列、访谈、评论 | 焦虑时要确定感，探索时要惊喜，赶时间时要少一步 |
| 要让人记住什么？ | growth 亮点假设 H1、pm 的 Aha | 签名时刻放在哪一步 |

## 2. 参考研究（联网，30 分钟内）

- 找 3–6 个参考：直接竞品 1–2 个、**跨品类的最佳实践** 2–3 个（解决同类任务的其他领域产品）、一个你认为做得差的反例。
- 每个参考只记三件事：**值得借鉴的一个机制**、**要避免的一个问题**、**它的签名时刻是什么**。
- 引用 URL 与访问日期；只借机制，不抄视觉。

## 3. 发散：让方向在「结构」上不同

同一个布局换三套配色 = 一个方向。用下面的轴组合出差异：

| 轴 | 例 |
|---|---|
| 信息组织 | 网格卡片 · 列表 + 预览 · 时间线 · 画布 / 看板 · 对话式 |
| 主交互模式 | 浏览选择 · 搜索优先 · 引导向导 · 智能推荐先行 · 模板起步 |
| 价值出现方式 | 先给结果再给设置 · 先设置再出结果 · 边做边预览 |
| 密度与节奏 | 高密度专业工具 · 舒展的展示感 · 渐进披露 |
| 情感基调 | 冷静可靠 · 温暖陪伴 · 高效利落 · 有趣有料 |

建议：D1 = 与现有产品/竞品最接近的「稳妥方向」；D2 = 围绕 Aha 重新组织的「价值优先方向」；D3 = 至少改变一个主轴的「大胆方向」。

## 4. 签名时刻（每个方向必答）

签名时刻 = 用户会记住、会跟别人说、会截图分享的**那一刻**。

| 要素 | 问题 |
|---|---|
| 位置 | 在哪条旅程的哪一步？（最好就是 Aha） |
| 触发 | 用户做了什么，或系统在什么时机出现？ |
| 表现 | 视觉 / 动效 / 文案 / 声音 / 数据呈现，具体到时长与缓动 |
| 意义 | 它强化了哪条价值（growth 亮点）？ |
| 代价 | 实现复杂度、性能、可访问性（减少动效时的替代） |

例：「上传完成后，报表不是一次性出现，而是按『识别到的指标』逐项渐显（每项 120ms），最后顶部出现『已为你识别 12 个指标』——用户第一次感到系统『懂』他的数据。」

## 5. 情感化设计三层（检查方向是否完整）

| 层 | 问题 | 常见缺失 |
|---|---|---|
| 本能层（第一眼） | 第一屏是否清爽、有层次、有品牌性格？ | 默认组件堆砌、层级扁平 |
| 行为层（使用中） | 关键任务是否顺、快、可预期、可撤销？ | 多余步骤、无反馈的等待、错误无出路 |
| 反思层（用完后） | 用户是否觉得自己更专业 / 更省心 / 想分享？ | 完成后没有「成就」与「下一步」 |

## 6. 快速做可点击原型

- 每个方向一个目录：`02-shape/prototypes/d1/index.html`，单文件 HTML + 内联 CSS/JS，**双击即可打开**。
- 用真实感数据（从 spec 示例、现有产品数据形态抄），不用 lorem ipsum。
- 覆盖主旅程到 Aha 的关键屏（通常 2–4 屏），加一个空态和一个错误态。
- 可以临时定义 tokens，但颜色、字号、间距要成体系（留给 specify 阶段收敛到 `design-system.md`）。
- 截图：`bash PLUGIN_ROOT/scripts/ui-evidence.sh 02-shape/prototypes/d1/index.html 02-shape/prototypes 375,1440`（用 `UI_EVIDENCE_NAME=d1` 指定文件名前缀），然后**打开 PNG 看**。
- 截图看完再写方向描述；看的时候问：第一眼的焦点在哪？Aha 那一屏够不够显眼？手机上是否挤？
- **缺陷检查（每张截图，推荐前必做）：** 元素重叠或遮挡 · 文字截断或溢出 · 375 宽下横向滚动或挤压 · 对齐与栅格断裂 · 对比度不足 · 占位文字 / lorem / 空白图 · 图标缺失或错位 · 状态不完整（空态、错误态）。发现一处就改原型、重新截图、再看一遍；在 design-directions.md 的「缺陷检查」逐张写结论（无 / 已修复：什么）。带着可见缺陷的方向不能被推荐。

## 7. 方向评审量表（自评 + 给人选择时展示）

每项 1–5 分：

| 维度 | 1 分 | 5 分 |
|---|---|---|
| 价值路径 | Aha 被埋在第三屏 | 首屏即通向 Aha，步数最少 |
| 签名时刻 | 没有或说不清 | 具体、可演示、与亮点一致 |
| 可用性 | 需要解释才能用 | 首次用户不看说明能完成主任务 |
| 一致性 | 与 design-system 冲突且无理由 | 一致，或有意且记录的演进 |
| 可访问性 | 对比度 / 焦点 / 动效有硬伤 | 底线全过 |
| 实现代价 | 需要新基础设施 | 现有组件与模式可承载 |
| 反默认 | 命中 AI 默认风格簇且无理由 | 为这个产品做了选择 |

推荐方向时引用分数与截图，不写「更现代、更高级」。理由必须落到**谁、在旅程哪一步、签名时刻如何发生**。下面这些不是理由：「最接近操作者参考图」「最稳妥 / 最常见」「看起来更专业」。参考图是输入，不是评分标准；命中 AI 默认风格簇（紫蓝渐变、玻璃拟态、emoji 图标、千篇一律的圆角卡片网格）又没有为这个产品说明理由，「反默认」记 1 分。

## 8. 常见坑

| 坑 | 纠正 |
|---|---|
| 只做了稳妥方向 | 强制 D3 改变至少一个主轴 |
| 方向描述写得很美，截图很平 | 以截图为准，改原型而不是改描述 |
| 签名时刻放在设置页 | 放在价值路径上 |
| 把参考图直接照搬 | 借机制不借皮 |
| 忽略移动端 / 窄屏 | 每个方向至少 375 与 1440 两张截图 |
| 推荐的方向截图里有重叠、截断、错位 | 推荐前逐张做缺陷检查；有缺陷先修再推荐（2026-09-17：推荐方向带渲染缺陷被选中） |
| 用「最像参考图」当推荐理由 | 参考图只说明操作者喜欢什么；推荐理由写用户、旅程步与签名时刻 |
