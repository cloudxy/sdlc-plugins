# 局部重设计：保留可操作性与数据语义

适用于已有页面、菜单、媒体库或供应商配置的 reuse / local-refinement。先沿已接受的任务和设计基线记录受影响入口、动作、条件与结果；改样式后逐项核对。功能迁移或收进“更多”不应使原有能力失去可发现入口。若确需改变业务行为，交相应决定人处理。

## 参考对象与加载契约

用户指定参考站时，核对实际页面、登录状态、日期与观察范围；读到的源码和亲自操作所得分别标明。登录后从阻塞点继续，沿用已给授权。参考站不能访问时，把未核对项留为未知，不用经验补成已观察事实。

列表交接写清：自动滚动或手动续载、首批数量、追加数量、分组/单张等模式的起始量、哪些筛选会重置、剩余数的单位、结束提示及失败恢复。不同来源可以采用不同方式；视觉统一不意味着强行统一加载行为。原站的显示批量也不等于本系统 API 的上限。

未知数量记录为待核实，附验证负责人；区分亲自观察、源码所得与设计建议，不用默认值补成事实。计数、已显示与剩余量使用同一筛选身份及单位；交接旧响应隔离与重复续载的预期，未定项不阻断其余已确定设计。

## 卡片、详情与常驻操作

- 以识别对象和下一步动作为主次。完整人物、设定板或需检查细节的媒体，明确自然比例、裁切与留白策略；不要让旧容器的 padding / max-height 无意决定内容展示。
- 定义主图/备份、角度、白模/深度和多视角的当前选择，交接操作针对的对象与版本；缩略图切换之后，预览、引用、加入项目和下载仍须指向同一选择。
- 常用动作可直接看到；次要动作进入更多菜单仍保留完整标签与键盘入口。图标加文字、相邻区域等宽等已接受要求写入规格，不在实现中猜占比或省略文字。
- 授权配置复用同站其他供应商的层级、控件与反馈模式。绿灯或“已就绪”对应哪条通道、哪一级证据要明确，并有文字说明；已登录、已选用、服务端支持和本次生成成功分别表达。

模式卡分别声明当前浏览、配置持久化、生效选择和执行动作的状态归属及写入时机；沿现有已接受的切换语义，不让浏览/刷新意外覆盖配置，也不把保存配置当成选用该通道。语义不明时交负责人确认，不由设计新增隐式选用规则。

## 本次工作、提交快照与历史回看

生成、导出、转换等异步工具要分别定义当前输入草稿、已提交输入、正在执行的请求、本次结果和已保存历史。结果区标明对应哪次提交，不能只因“有一张图”就呈现为本次成功；执行中编辑草稿时，说明改动用于下一轮，或沿现有规则锁定相关字段。

将首次进入、浏览器刷新、同一页面内往返、新一轮开始、失败和显式打开历史分别列入状态矩阵，写清每项恢复什么、清空什么及操作目标。刷新是否恢复上次结果取决于用户要求与产品基线；若要求新工作位为空，保留历史数据而不自动把最新历史填入结果区。阅读型工作台也可以恢复原选中项，不能把某个生成台的选择推广成全站清空规则。历史回用明确是提示词、参考、参数还是整份输入，覆盖前后的含义保持一致。

将“未收到结果”“新结果已产生但转存失败”“媒体已存而记录保存失败”分开设计。旧结果若保留，应标为上次结果，并保留仍需抢救的字节或回执；不能让旧图替新请求报成功，也不能为清空展示而删掉历史或唯一未保存结果。沿现有能力提供下载、恢复存储或读取原回执；缺少恢复接口时注明待实现，不在原型中冒称已有。未知提交和仅保存失败都不能默认再次生成并产生新用量。

用具体动词定义随机、清空、重置、复用、复制和保存的作用范围：改了哪些输入、结果是否受影响、可否恢复。成功提示以实际剪贴板写入、持久化提交或原回执为依据，API不可用或失败给可执行恢复；不能因按钮处理器走到末尾就显示成功。

验收至少走完一条当前结果→历史→刷新或返回路径，并改变一次响应状态核对结果身份；若涉及部分成功，再验证保存恢复不重发生成。适用的窄屏和长文案检查要看到主动作、错误与返回，不能用挤窄参考卡、隐藏控件或把结果排到很远处换取形式整齐。按实际工具区分源码推断、合成原型、运行页面和真人试用。

## 交互与断点

用户会连续调整的表单或参数区，声明局部变化后的阅读位置、焦点、选择和展开状态。把实际滚动宿主纳入交接，包含组件外的工作区或文档；不能把保留组件自身位置等同于页面连续性。只在业务确需定位新内容时设计显式滚动，不以重绘副作用代替导航决定。

成功提示按当前需求声明显示、开始渐隐和移除的时序，以及手动关闭的位置、标签和减少动效行为；例如“显示3秒后渐隐”要与“3秒内已消失”区分。错误、未保存输入及恢复入口分别确定保留策略，不沿用某次成功提示的时间。说明新提示替换旧提示时的预期，避免旧计时器误关新内容。

菜单规格包含打开后点击子项到实际内容操作、指针跨越边界、失焦、Escape、外部点击与关闭后焦点归位；只验收展开/收起会漏掉“看得到但点不到”。焦点可见性保留在可交互控件上；结构宿主的异常轮廓交前端诊断，不能通过去掉全站焦点样式掩盖。

触发器、浮层和子菜单组成同一交互区域；移焦进入子项不能当成离开。分别定义跨指针间隙与明确离开整个区域的行为。菜单由 Escape 关闭时返回触发器；外部点击或 Tab 离开时保留正常目标焦点；执行子项后沿实际目标内容的焦点契约，不能统一抢回触发器。

横向分类在初始进入与切换后应看得到当前项。窄屏核筛选顺序、卡片列数、浮条和关闭按钮是否完整可达；固定浮条需给列表尾部留出可操作空间。菜单或浮层向上/向下展开取决于实际可用空间，不能只在大屏短卡片上判断。

## 共享控件跨宿主的一致性

当同一菜单、工具条或设置控件复用到不同页面主题，或同行控件使用不同原生标签时，列出受影响宿主，声明组件自身保持不变的属性与允许的语义变体。按已接受的设计 token 明确尺寸、字号/行高、内边距、圆角、描边、图标对齐及关闭/展开/选中/hover/focus 状态；`summary` 与 `button` 不会因为功能相近就自动获得相同基线。

主操作、危险操作及明确批准的明暗主题可以有各自的颜色、字重或形状变体；差异应来自已声明的用途，不应由祖先容器偶然决定。共享导航控件一致，不要求把页面正文、业务含义或所有按钮统一换肤。交接时给出相关宿主和状态的对照条件，运行页复核沿下游实现与 QA 的原有路径完成，不另加全站验收门。

## 交付边界

在与原型相同条件下查看运行页面，并实际走到关键动作的结果。分别记录设计建议、原型渲染、DOM 测试、实际页面和具名人工接受；父代理的截图或转述注明执行者与范围，不能写成设计师独立验收。没有测试到的断点、输入方式或状态继续标为未验证。
