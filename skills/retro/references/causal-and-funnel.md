# 因果推断、漏斗与留存

## 因果推断阶梯

**你能得出多强的结论，取决于你有什么数据结构。**

| 方法 | 结论强度 | 前提 |
|---|---|---|
| **随机对照实验** | 因果（最强） | 能随机分流 |
| 断点回归（RDD） | 较强因果 | 有明确阈值切分（如「满 100 减 20」） |
| 双重差分（DID） | 较强因果 | 有可比对照组 + 处理前趋势平行 |
| 合成控制 | 较强因果 | 有多个对照单元可加权构造 |
| 倾向得分匹配（PSM） | 中等 | 混淆变量都可观测（**很强的假设**） |
| 前后对比 + 无对照 | **仅「变化」** | — |
| 相关性分析 | 仅「相关」 | — |

**无对照组时只能说「变化」，不能说「因为」。** 这不是学术洁癖：把相关当因果会导致下一轮把资源投在错误的地方。

## 前后对比的三个混淆源

```
「上线导出功能后，处理时长下降 8%」

混淆源 ① 季节性
  8 月是业务淡季，历史上淡季处理时长平均低 5%
  → 检验方法：对比去年同期、看历史同月数据

混淆源 ② 同期其它变更
  同期还上线了工单自动分类、调整了工单分配规则
  → 检验方法：列出同期所有变更（问 /sre 拿发布记录）

混淆源 ③ 外部因素
  竞品出故障导致部分用户迁入、行业淡旺季、政策变化
  → 检验方法：看外部数据、问 /ops
```

**「列出同期所有变更」是必做步骤**。团队通常同时上线多个东西，然后把改善归因给自己最关注的那个。

## 双重差分（最实用的准实验方法）

**适用**：无法随机分流，但有一个未受影响的可比群体。

```
              处理前    处理后    差值
实验组（A 区）  100      130      +30
对照组（B 区）  100      110      +10
                                DID = +20

结论：排除了共同的时间趋势（+10），处理效应约 +20
```

**关键假设：处理前趋势平行**。必须验证：

```
画出处理前若干期的两组趋势线
  平行 → DID 假设成立 ✅
  不平行 → DID 无效（两组本来就在以不同速度变化）
```

**不检验平行趋势的 DID 是无效的**，这是最常见的误用。

## 选择偏差

**最隐蔽的归因错误。**

```
「使用导出功能的主管，处理时长比不用的低 12%」
→ 结论：导出功能提升效率？

反驳：使用导出的主管本来就是效率更高的人
     检验：看这批主管在功能上线之前的处理时长
     结果：上线前就比平均低 12%
→ 差异完全由选择偏差解释，功能效应无法识别
```

**检验方法：看处理前的基线**。如果使用者在使用之前就已经不同，那么差异不能归因于使用。

同类形态：

- 「参加了培训的员工业绩更好」（愿意参加培训的本来就更积极）
- 「用了新功能的用户留存更高」（活跃用户才会去试新功能）
- 「订阅了推送的用户更活跃」（活跃用户才订阅推送）

**这类结论几乎总是被选择偏差污染**，除非有随机分配。

## 漏斗分析

### 步骤定义要严谨

```
步骤定义必须回答：
  ① 允许跳步吗？（用户直接从步 1 到步 3 算不算通过步 2）
  ② 回退算什么？（走到步 3 又回到步 2）
  ③ 多次尝试怎么计？（同一用户尝试 3 次，第 3 次成功）
  ④ 时间窗多长？（进入漏斗后多久内完成才算转化）
```

不定清楚，两个人算出的漏斗数字不一样。

### 看绝对流失量，不只看转化率

```
步骤        进入      转化率    绝对流失
浏览列表   100,000    85%       15,000    ← 流失量最大
点击导出    85,000    92%        6,800
配置确认    78,200    40%       46,920    ← 流失量与转化率都差，优先修
下载完成    31,280    98%          626
```

**只看转化率会误判优先级**：某步转化率 40% 但只有 200 人进入，另一步 85% 但有 10 万人进入——后者绝对流失量大得多。

**优先级 = 绝对流失量 × 可改进空间**。有些步骤的低转化率是合理的（配置确认步骤的流失可能是用户改变主意，不一定是问题）。

### 分维度看

**总体漏斗常掩盖特定群体的问题：**

```
总体：配置确认转化率 40%
  桌面端：52%
  移动端：11%   ← 问题在这里，可能是移动端布局有问题
```

常用维度：设备、渠道、新老用户、地域、租户规模、浏览器。

### 漏斗与定性结合

漏斗告诉你**在哪流失**，不告诉你**为什么**。找到最大流失点后：

- 看录屏/热图（如果有）
- 找 `/ops` 拿这个环节的用户反馈
- 做可用性测试（5 个用户就能发现大部分问题）

**「配置确认步骤流失 60%」+「用户反馈说不知道该选哪些列」= 可行动的结论。**

## 留存分析

### 按同期群（cohort）看

```
❌ 混在一起：「30 日留存 42%」
   —— 掩盖了趋势：可能 1 月进来的用户留存 60%，8 月的只有 25%

✅ 按 cohort：
   注册月    D1     D7     D30
   2026-05   65%    48%    42%
   2026-06   63%    45%    38%
   2026-07   58%    38%    30%   ← 持续下降，需要查原因
   2026-08   52%    31%    —
```

**趋势比绝对值重要**：留存在下降说明有系统性问题（渠道质量下降？产品变差？竞品抢夺？）。

### 看曲线形状

```
健康：快速下降后走平
     ██▆▄▃▃▃▃▃▃  ← 走平说明有稳定的核心用户群

危险：持续下降不走平
     ██▆▅▄▃▂▁▁▁  ← 没有形成留存，产品价值未被感知
```

**走平的位置就是产品的「自然留存率」**。它是产品价值的最直接体现。

### 留存的定义要明确

```
「留存」= 什么行为？
  登录 → 最宽松，可能高估
  完成核心动作 → 更有意义
  付费 → 最严格

「D7 留存」= 第 7 天当天活跃？还是第 1–7 天内任意一天活跃？
  两个口径的数字差很多
```

## 归因的常见陷阱

| 陷阱 | 表现 | 处理 |
|---|---|---|
| 选择偏差 | 使用者本来就不同 | 看处理前基线 |
| 幸存者偏差 | 只分析留下来的用户 | 把流失用户纳入分析 |
| 辛普森悖论 | 总体趋势与分组趋势相反 | 分维度看，找混淆变量 |
| 回归均值 | 极端值自然回落被当成干预效果 | 用对照组 |
| 多重比较 | 试很多切片必有「显著」的 | 预先定义切片；或校正 |
| 时间滞后 | 效果需要时间显现，过早判断 | 定合理的观察窗口 |
| 归因窗口 | 转化归给哪次触点 | 明确归因模型（首触/末触/多触） |

### 辛普森悖论（值得单独理解）

```
总体：新版转化率 4.5% < 旧版 5.0%   ← 新版更差？

分设备看：
  桌面端：新版 8.0% > 旧版 7.5%    ← 新版更好
  移动端：新版 2.0% > 旧版 1.8%    ← 新版更好

原因：新版流量里移动端占比更高（移动端本身转化低）
     → 总体被流量结构差异掩盖
```

**遇到「总体与分组结论相反」时，必须找出混淆变量。** 直接用总体结论会做出错误决策。

## 报告纪律

### 结论先行

```
✅ 结论：配置确认步骤是最大流失点（4.7 万人流失，转化率 40%），
        移动端尤为严重（11%）。建议优先优化移动端配置界面。
        （数据来源与口径见下，反驳自检见末节）

❌ 先铺陈 20 张图，最后一页写结论
```

### 必须带三样

```
① 样本量 —— 「提升 50%」可能是 2 人变 3 人
② 时间窗与口径 —— 「本周」是自然周还是滚动 7 天
③ 置信区间或波动范围 —— 单个数字掩盖不确定性
```

### 反驳自检（≥2 个替代解释）

每个结论后面附：

```
替代解释 1：<...>
  检验：<怎么查的>
  结果：<已排除 / 无法排除，影响是 ...>

替代解释 2：<...>
  ...

修正后的结论：<考虑了以上之后的结论，标明不确定性>
```

**这一节是分析质量的分水岭。** 不做反驳自检的报告会给出过度自信的结论。

### 数据安全

- **不直连生产主库跑重查询** —— 走只读副本或数仓
- 报告**不含明文个人信息** —— 脱敏或聚合（最小聚合粒度：≥5 人的分组）
- 敏感指标（收入、成本）按权限分发
