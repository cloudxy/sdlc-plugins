# 实验设计

## 六项必填

缺任一项的实验都会在解读阶段出问题。

## ① 假设：必须可证伪

```
❌ 「新入口会提升用户体验」           —— 无法证伪
❌ 「优化后效果会更好」               —— 「更好」是什么
✅ 「把导出入口从二级菜单移到列表工具栏，
     会使导出功能周使用率从 12% 提升至 20% 以上」
```

可证伪的假设包含：**具体改动 + 具体指标 + 基线值 + 预期方向与幅度**。

## ② OEC 与护栏

### 明确主要决策指标与冲突处理

通常选择一个主要指标简化决策；多个共同主要指标需预先约定决策规则及适用的多重比较处理。否则两个主指标冲突时无法决策：使用率涨了但处理时长没变，算成功还是失败？

**OEC 要选离用户价值最近的**，不是最容易涨的。使用率是驱动指标不是 OEC——用了但没变快，功能就是失败的。

### 护栏必须有

| 实验 | 护栏 |
|---|---|
| 简化注册流程 | 注册后 7 日留存（防引入低质用户） |
| 增加推送 | 退订率、卸载率 |
| 新增导出入口 | 列表页 P95、导出失败率、整体处理时长 |
| 推荐算法改版 | 内容多样性、长尾曝光占比 |

**护栏要有红线值**，突破即停止实验。

## ③ 分流

### 分流单位

| 单位 | 何时用 | 风险 |
|---|---|---|
| 用户 | 默认 | 同用户多设备可能不一致 |
| 会话 | 短期效应 | 同用户体验不一致，不适合改变界面的实验 |
| **租户/团队** | **有交互效应时** | 样本量骤减（租户数远少于用户数） |
| 地域 | 需要地域隔离 | 地域间本身有差异，可比性差 |

**交互效应（干扰）是最容易被忽略的问题**：

```
多租户系统里按用户分流：
  同租户内 A 组用户看到新界面，B 组看到旧界面
  → 他们会互相讨论、互相影响、甚至互相帮助操作
  → 实验组与对照组不再独立，效应被稀释或放大
→ 应按租户分流
```

同类场景：社交功能（好友互相影响）、协作工具（同团队内）、市场类产品（供需两侧）。

### 随机化

```
✅ hash(user_id + experiment_salt) % 100 < 50 → 实验组
   同一用户始终同组；不同实验用不同 salt（避免实验间相关）
```

**不要用「用户 ID 尾号」分流**：ID 可能不随机（连号注册、批量导入的用户特征相似）。

### 分组均衡性检验（事前必做）

分流后、实验开始前，检查两组的**历史指标**是否可比：

```
组 A（n=5200）：历史周使用率 11.8%，平均工单量 42/周
组 B（n=5180）：历史周使用率 12.1%，平均工单量 41/周
→ 差异在正常波动内 ✅

若发现显著差异 → 重新分流（换 salt），或在分析时做协变量调整
```

**不检验就可能一开始就有偏差**，实验结果无法解释。

## ④ MDE 与样本量

### 先算样本量，再决定要不要做实验

```
输入：
  基线转化率 p = 12%
  MDE = +3 个百分点（绝对）→ 目标 15%
  显著性水平 α = 0.05（双侧）
  统计功效 1-β = 0.8

输出：每组约需 n ≈ 2 × (1.96+0.84)² × p(1-p) / MDE²
     ≈ 每组 1900 样本（粗算，精确值用工具）

日均可分配流量 500 → 需 (1900×2)/500 ≈ 8 天
```

**算出来要跑三个月的实验通常不值得做。** 这时的选择：

| 选择 | 说明 |
|---|---|
| 放大 MDE | 只检测更大的效应（+8 个点而非 +3 个点） |
| 延长实验 | 但要注意时间跨度带来的外部变化 |
| 提高基线流量 | 把实验放在流量更大的入口 |
| **放弃实验** | 改用灰度观察 + 定性研究 |

**不要在样本量不足时硬跑**：结果不显著时你无法区分「真的没效果」和「样本不够检测不出」。这会导致错误地放弃一个有效的改动。

### MDE 怎么定

**从业务价值倒推**：多小的提升值得为这个改动买单？

```
改动成本：2 人周
预期收益：使用率每提升 1 个百分点 ≈ 每月节省 <n> 人时 ≈ ￥<n>
→ 需要至少提升 3 个百分点才回本
→ MDE = 3 个百分点
```

MDE 定得太小 → 样本量爆炸；定得太大 → 检测不到有价值的改进。

## ⑤ 停止规则：禁止 peeking

### 为什么 peeking 是作弊

**反复看结果并在显著时停止，会大幅提高假阳性率。** 直观解释：随机波动会让 p 值在实验期间上下浮动，看的次数越多，撞上「偶然显著」的概率越大。

```
只在结束时看一次：假阳性率 = 5%
每天看一次，看 14 天，显著就停：假阳性率远高于 5%
```

很多人不知道自己在作弊——「我只是每天关注一下进展」。

### 正确做法

| 方法 | 说明 |
|---|---|
| **固定时长/样本量** | 预先定「跑满 14 天或 3800 样本才看 OEC」（最简单） |
| 序贯检验 | 允许多次查看，但每次的显著性阈值更严（需要正确实现） |
| 贝叶斯方法 | 报告后验概率而非 p 值，对多次查看不敏感 |

**中途可以看的只有护栏指标** —— 为了及时止损。看护栏不影响 OEC 的统计有效性（因为不用它做「是否有效」的决策）。

### 实验时长的其它考虑

| 因素 | 说明 |
|---|---|
| 覆盖完整周期 | 至少 1 个完整周（周末与工作日行为不同），最好 2 周 |
| 新奇效应 | 新界面初期可能有短暂提升，2 周后消退 → 实验要够长 |
| 学习效应 | 复杂功能用户需要时间学会 → 短实验会低估效果 |
| 不要跨大促/节假日 | 行为模式完全不同 |

## ⑥ 回滚阈值

```
任一满足即立即停止实验：
  护栏指标突破红线（列表页 P95 > 1000ms）
  错误率显著上升
  出现数据不一致
  用户投诉明显增加
```

与 `/sre` 的灰度回滚判据一致——**提前写死，不临场判断**。

## 常见作弊方式（避免，也要能识别）

| 作弊 | 表现 | 后果 |
|---|---|---|
| **peeking** | 反复看，显著就停 | 假阳性率飙升 |
| **p 值猎取** | 试多个指标，报显著的那个 | 20 个指标里必有 1 个 p<0.05 |
| **切片挑选** | 总体不显著，找一个显著的子群报 | 事后找的子群没有统计意义 |
| 改变 OEC | 主指标不显著，改用次指标当主指标 | 事后合理化 |
| 排除异常值 | 排除「不利」的数据 | 除非预先定义排除规则 |
| 延长实验直到显著 | 一直跑到 p<0.05 | 等价于 peeking |
| 忽略护栏 | 只报 OEC 提升，不报护栏恶化 | 隐藏成本 |

**防范手段：预先注册（pre-registration）** —— 实验前把假设、OEC、护栏、切片、停止规则全部写进文档并冻结。事后想改就必须显式说明是探索性分析（探索性发现需要新实验验证，不能直接下结论）。

## 结果解读

### 显著性与实际意义

```
p < 0.05 且提升 0.3 个百分点：统计显著，但业务上可能不值得
p = 0.08 且提升 5 个百分点：不显著，但可能值得继续验证（加大样本）
```

**报告要同时给出**：效应大小（点估计）、置信区间、样本量、p 值。

**置信区间比 p 值信息量更大**：
```
提升 3.2 个百分点，95% CI [0.5, 5.9]
→ 效应方向确定为正，但幅度可能小到 0.5（不值得）也可能大到 5.9（很值得）
→ 结论：有效但幅度不确定，建议扩大样本或直接上线观察
```

### 不显著不等于没效果

```
不显著的三种可能：
  ① 真的没效果
  ② 有效果但样本量不足检测不到
  ③ 效果在不同子群相反，总体抵消了（要看预先定义的切片）
```

**报告要说明是哪一种**（至少排除 ②：报告实际达到的功效）。

## 实验之外的证据

样本量不足或不适合做实验时，这些手段仍然有价值：

| 手段 | 能得出什么 |
|---|---|
| 灰度 + 前后对比 | 弱因果（要控制同期变更） |
| 断点回归 | 较强因果（有明确的阈值切分时） |
| 双重差分 | 较强因果（有可比的对照群体时） |
| 定性研究（访谈/可用性测试） | 机制理解（为什么，而非多少） |
| 定性 + 定量结合 | 最实用：定性找假设，定量验证规模 |

**不能做实验不等于只能靠感觉。** 说明用了什么替代方法、它的假设是什么、结论强度如何。
