# 精准营销：对的人 × 对的信息 × 对的渠道 × 对的时机 × 对的权益

阶段 `launch`（L3，qc 放行之后，与 sre 发布、ops 教/开/告并行）。**每一次触达都是一次实验**：有目标、有护栏、有对照、能复盘。

## 1. 人群：必须能被数据算出来

| 维度 | 例 | 来源 |
|---|---|---|
| 行为 | 近 7 天导入过数据但从未查看报表 | `tracking-plan.yaml` 事件 |
| 生命周期阶段 | 新注册未激活 / 已激活 / 活跃 / 沉默（14 天未访问）/ 流失 / 回流 | `tags.yaml` 生命周期标签 |
| 价值 | RFM：最近一次、频次、金额；付费套餐 | `tags.yaml` 价值标签 |
| 意图 | 访问定价页 ≥2 次、试用到期前 3 天 | 事件 + 规则标签 |

每个人群写清：**标签 id 组合、规模估计、排除规则**（已付费、近期已触达、退订、未成年人、内部账号）。

**算不出来的人群不能投。** 缺的事件/标签写成需求交给 pm（埋点）和 data-warehouse-engineer（标签）。

## 2. 生命周期与触发式触达

| 阶段 | 目标 | 典型触发 | 指标 |
|---|---|---|---|
| 访客 → 注册 | 获客 | 着陆页、内容、投放 | 注册转化率 |
| 注册 → 激活 | 到达 Aha 时刻 | 注册后未完成关键动作 N 小时 | 激活率（首次到达 Aha） |
| 激活 → 习惯 | 形成复用 | 第 2、7 天未回访 | 次日 / 7 日留存 |
| 活跃 → 付费 | 变现 | 触达用量上限、访问定价页 | 付费转化率 |
| 沉默 → 回流 | 召回 | 14 天未访问 + 有新能力与其相关 | 回流率 |
| 付费 → 推荐 | 裂变 | 达成里程碑时 | 邀请率、K 因子 |

触发式（行为发生后按规则触达）通常比批量群发更有效、更少打扰，优先设计。

## 3. 触达矩阵

| 人群（标签 id） | 规模 | 信息（引用已核验卖点） | 渠道 | 时机 | 权益 | 目标指标 id | 护栏 |
|---|---|---|---|---|---|---|---|
| lifecycle=activated_no_report | ~3,200 | 「上传后 30 秒出报表」+ 一键示例 | 站内信 + 邮件 | 导入完成 10 分钟后未查看 | 无 | report_first_view_rate | 退订率 < 0.5% |

信息只能引用 `accept-growth.md` 中 ✅ 或改写后的说法。

## 4. 渠道选择

| 渠道 | 适合 | 成本 / 限制 | 合规要点 |
|---|---|---|---|
| 站内信 / 应用内提示 | 已登录用户、上下文相关 | 几乎免费；打扰要控频 | 可关闭 |
| Push | 移动端召回、时效性 | 过度推送导致卸载 | 系统授权、夜间免打扰 |
| 邮件 | 内容较长、ToB | 送达率、垃圾箱 | 退订链接 |
| 短信 | 强时效、关键通知 | 单价高 | 营销短信须事先同意、退订方式 |
| 社群 / 公众号 / 内容 | 教育、口碑 | 慢，需持续运营 | 平台规则 |
| 付费投放 / SEO / ASO | 获客 | CAC；需归因 | 广告法用语 |

选择依据：**渠道-人群匹配**（这群人在哪、在什么时刻愿意接收）> 成本 > 规模。

## 5. 实验设计（每个活动必填）

| 项 | 要求 |
|---|---|
| 假设 | 「对 X 人群在 Y 时刻发送 Z，会让指标 M 提升」 |
| 目标指标 | `metrics.yaml` 中的 id；口径不自己定义 |
| 护栏指标 | 退订率、投诉率、卸载率、退款率、客服工单量——各给红线 |
| 对照 | holdout（如 10% 不触达）或 A/B；随机分组，分组规则写清 |
| 样本量 | 按基线与最小可检测效应（MDE）估算；不够就延长周期或合并人群 |
| 周期与停止规则 | 预先写死；中途不看结果改方案；护栏越线立即停 |
| 读数 | 交 analyst，按预注册口径出结论（含置信区间） |

## 6. 频控与合规

- 每人每周营销触达上限（跨渠道合计），高价值用户与新用户单独控频。
- 同意依据：营销短信/邮件需用户同意；遵守个人信息保护相关法律与平台规则；未成年人不做营销触达。
- 敏感人群与敏感时机（刚投诉、刚退款）排除。
- 文案遵守广告法：不用「最」「第一」等绝对化用语，数字写清条件。

## 7. 增长回路（可选，写进 growth.md）

| 回路 | 步骤 | 关键指标 |
|---|---|---|
| 邀请回路 | 用户获得价值 → 邀请同事 → 同事注册并获得价值 → 再邀请 | 邀请率 × 受邀转化率 |
| 内容回路 | 用户产出可分享内容（报表链接）→ 访客看到 → 注册 | 分享率 × 访客注册率 |
| 付费回路 | 收入 → 投放 → 新用户 → 收入 | LTV / CAC |

回路里每一步都要有对应事件，否则无法诊断断在哪。

## 8. 与发布节奏对齐

- sre 灰度未全量前，不做大规模投放。
- 触达计划写明「依赖的发布阶段」与「暂停条件」（告警、回滚）。

## 反模式

| 反模式 | 修正 |
|---|---|
| 全量群发 | 按生命周期拆人群，触发式优先 |
| 没有对照组就宣布「活动提升 30%」 | holdout + 预注册指标 |
| 用未核验的卖点做文案 | 只用 `accept-growth.md` 通过的说法 |
| 各渠道各自控频 | 跨渠道合计频控 |
| 活动结束不复盘 | 实验记录写入 `growth.md`，analyst 读数 |
