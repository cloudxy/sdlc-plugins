# 已明确复刻目标时的范围与证据

适用于用户已选定参考产品、页面或模块的比较/复刻取证。沿原 snapshot 返回观察和约束；不据此取得实现、下载整站、登录或发布权限。已有明确采用决定时引用该决定，不重开一轮“是否要复刻”的批准。

## 把“1:1”拆成可验收的对象

按本次范围区分布局、交互、数据、资源字节和运行行为。为相关入口记下版本/观察时间、触发动作、输入、产出、关联详情/预览/复制/下载以及未知部分。只看到列表或截图，不能推断详情数据、下载内容或服务端私有方法相同。

当交付含本地/离线资源时，给实施者一份资源清单：

| 项 | 需要辨清的事实 |
|---|---|
| 覆盖集合 | 所有相关分类、分页、详情、浮层和预览；区分资源记录数与唯一文件数 |
| 资源形态 | 视频/音频、封面、技能图、字体等；包括脚本内嵌 data URI、CSS 引用、分段媒体的依赖 |
| 关联关系 | 哪个对象/版本使用哪份资源；原始媒体与变换后的封面不是同一字节对象 |
| 交付边界 | 用户要求本地保存还是允许在线引用、哪些外链例外已明确；来源地址与实际读取地址分开 |
| 证据缺口 | 未取得、未播放、未核对的内容逐项注明；替代图或占位图需要单独说明 |

URL 目录不证明文件已保存，文件存在不证明页面正在读它。观察材料不足时保留缺口；实际取回/服务资源由获授权的实现任务完成。普通竞品调研不自动扩为完整离线镜像。

## 交接判据

- 已观察到的行为与推测分列，范围对应用户要求；不由一个公开界面声称恢复了私有算法或全部功能。
- 同一资源在多个入口的身份可追踪；本地化要求写入交付约束，实施细节交由原架构/实现职责决定。
- 提供原证据的位置、版本及缺口，不把资源清单或测试数量当作复刻完成证明。
