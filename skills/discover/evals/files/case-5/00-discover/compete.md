# Compete · 独立开发者 API 监控

## 集合

| 类别 | 代表 | 独立开发者怎么用 | 卡点 | 来源等级 |
|---|---|---|---|---|
| 现状 | 不监控，等用户反馈；或自写 cron 脚本定时请求接口 | 出事靠用户在社群里说 | 发现慢；脚本没人维护，挂了也不知道 | E1（12 份社区帖子与 5 次访谈） |
| 替代行为 | 通用拨测服务免费档 | 只配一个首页地址 | 只看通不通，不看返回内容对不对 | E2（产品页与免费档说明） |
| 直接 | 面向团队的 API 监控 SaaS | 少数人试用后放弃 | 起步价对个人偏高；配置面向团队 | E2（公开定价页） |
| 标杆 | APM 套件 | 基本不用 | 要装探针，超出个人维护能力 | E1 |

## 本变更一行

他们：团队向、按席位收费 | 现状：靠用户发现问题 | 我们若做：面向个人的“返回内容也检查”的 API 监控 | 差异化候选，尚未验证

## 第三方依赖

访谈中 3/5 人提到最近一次事故源自第三方 API（支付、大模型、邮件）返回格式变化，而不是自己的服务宕机。
