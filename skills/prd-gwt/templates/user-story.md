## 3C

### Card（是什么）

作为 <具体角色>，我想要 <能力>，以便 <价值>。

**角色要具体**：不是「用户」，是「每天处理 50+ 工单的客服主管」。角色写模糊，后面的场景和验收都会跟着模糊。

**「以便」不能是同义反复**：
- ❌ 以便我能导出工单（等于重复了「能力」）
- ✅ 以便我能把工单交给外部团队处理，不用手工复制 20 分钟

### Context（什么场景）

| 项 | 内容 |
|---|---|
| 什么时候用 | <触发时机：每周一整理上周积压时> |
| 多频繁 | <每周 1 次 / 每天多次> |
| 这之前用户在做什么 | <筛选出未结工单> |
| 这之后用户要做什么 | <发给外部团队，等回填> |
| 现在怎么做的（workaround） | <手工复制到 Excel，30 条约 20 分钟> |
| 不做会怎样 | <每周浪费 20 分钟；易漏易错> |

「这之后要做什么」经常揭示出更大的需求——如果用户导出后还要手工录回，那真需求可能是双向同步而不是导出。

### Confirmation（怎么算完成）

| GWT | 类型 | 内容 |
|---|---|---|
| GWT-1 | 正常 | **Given** <前置状态含具体数据> **When** <单个动作> **Then** <可观测结果> |
| GWT-2 | 空态/边界 | **Given** … **When** … **Then** … |
| GWT-3 | 越权 | **Given** … **When** … **Then** … |

至少三条。判定标准：`/qa` 拿着它能直接写用例，不需要回来问问题。

无不可测词：正确的 / 合理的 / 友好的 / 快速的 / 适当的 / 尽可能 / 必要时。
