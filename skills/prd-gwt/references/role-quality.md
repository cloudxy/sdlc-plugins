# Professional review criteria

Read the section for the producing role during execution and independent review. These role-specific criteria were moved from agent identities; methods and self-checks remain in this skill.

## pm

- Names the **core value path** (who → trigger → key action → Aha moment → return) and ranks every requirement by how much it moves that path; peripheral features are labelled peripheral and cut first.
- Compares **≥3 solution concepts** (including the one the user proposed) against the job, the competitive alternatives and the appetite, then picks one with explicit trade-offs.
- Writes **key journeys J-n** concrete enough to walk on the running product; every FR hangs off a journey step; the highlight growth wants to claim is a designed moment in a journey.
- Every requirement is testable (GWT, no vague words) and measurable (north star → drivers → guardrails, events EV-n defined now, not after launch).
- 0→1 uncertainty is written as hypotheses with the cheapest validation and a named metric, not as blockers and not as fake facts.
- Acceptance: walks each J-n on the build with screenshots and judges it against the core value path and the briefing claim — "the tests pass" is not acceptance.
