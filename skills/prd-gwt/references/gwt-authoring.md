# GWT 验收标准写法

## 先用实例形成共同理解

行为尚未明确时，区分故事、规则、具体例子和未决问题（[Example Mapping](https://cucumber.io/docs/bdd/example-mapping/)）。用相关的正常、边界或失败场景帮助比较；若用户答不上来，可提供明确标注为候选的结果及代价，按[共同对话方法](../../discover/references/discuss-protocol.md)讨论。结果未定就登记 Q-* 与阻塞范围，不编造 Then 来补齐格式。

已有规则和授权直接复用。重复/覆盖、权限或责任归属等影响业务结果的未定规则，不能因属于“运营细节”就默认为已可实现；给出建议，保持待确认并标明阻塞。决定后再把例子转换为 FR/GWT；下文标准针对交给实现/QA 的已接受行为，不要求发现阶段草稿提前完整。示例数值不自动成为本项目阈值。

## 判定标准与双向非孤儿门禁

一条验收项合格的唯一检验：**`qa` 拿着它能直接写出用例（或定性走查单），不需要回来问任何问题。** 同时满足 **PRD 双向非孤儿追溯门禁（`Goal/Metric ↔ Journey J-n ↔ FR-n ↔ GWT`）**：零孤儿 `FR-n`（每条 `FR-n` 标题必须向上挂靠业务指标 `metric:<id>@v<n>` 或显式假设 `A-n`，防镀金），零无验证 `FR-n`（每条 `FR-n` 必须向下落到可验证的 GWT 或概率黄金集评测行）。

（注：对于 `ai-agentic` 开放式概率输出，确定性 GWT 仅覆盖权限、工具边界、引用格式、超时回退、HITL 确认与成本上限；生成内容质量须按 [industry-product-sops.md](industry-product-sops.md) 绑定黄金评测集通过率与拒答/幻觉阈值，不伪装成 100% 字面量相等断言。）

需要回来问 = 不合格。常见的「需要回来问」：判断阈值多少、异常时显示什么、谁有权限、数据从哪来。

## 四段验收结构与定性逃生舱

每条验收项围绕 **`前提(Given) — 操作(When) — 预期结果(Then) — 判定标准`** 四段构造：

```
前提 (Given)     前置状态 —— 系统处于什么状态、用户是谁、数据是什么
操作 (When)      触发动作 —— 用户或外部系统做了一个具体操作（一个，不是一串）
预期结果 (Then)  可观测结果 —— 用户界面、响应体、导出物或审计边界发生什么变化
判定标准         通过判据 —— 精确数值阈值 / 字段枚举断言 / 黄金集指标；纯定性项启用「定性逃生舱」
```

**定性逃生舱（Qualitative Escape Hatch）**：当某项验收确属无法纯机器断言的主观视觉层级、语气或排版体验时，**严禁用模糊词糊弄**，必须在 `判定标准` 栏显式写明 **`判定依据 + 判定人`**（例如：`判定依据：<product_root>/design-system.md §3 信息层级与 ux-writing 错误文案三要素；判定人：designer（经 04-verify/accept-design.md 实机走查裁定）`）。

各段常见错误：

| 段 | 错误 | 修正 |
|---|---|---|
| Given | 「用户已登录」（太粗） | 「主管角色已登录，本周有 30 条未结工单」 |
| Given | 写了动作（「用户点击了列表」） | 前置状态不是动作，动作放 When |
| When | 一串操作（「登录后进入列表选中导出」） | 拆成 Given（已登录、已在列表）+ When（选中并导出） |
| When | 描述内部实现（「调用导出接口」） | 用户视角：「点击导出按钮」 |
| Then | 「导出成功」（不可观测） | 「下载得到 CSV 文件，含 30 行数据」 |
| Then | 描述实现（「写入 export 表」） | 用户能看到什么 |
| 判定标准 | 留空或写「体验良好 / 稳定及时」 | 写精确阈值（如 `行数=30，P95≤10s`），或写定性逃生舱 `判定依据 + 判定人` |

## 不可测词改写对照（含严格禁用词）

`体验良好`、`稳定及时`、`友好的`、`gracefully`、`正确的`、`合理的` 等模糊词**在任何情况下严格禁用**（即使启用定性逃生舱也不得使用）。改写方法统一是**问「怎么算」**：

| 不可测词（严禁出现） | 追问 | 改写 |
|---|---|---|
| 正确显示 | 正确是什么样？ | 显示「工单号/标题/创建时间/负责人」四列，按创建时间倒序 |
| 合理处理 / gracefully | 具体怎么处理？ | 保留已成功的 28 条，失败的 2 条列出原因，不崩溃不丢草稿 |
| 友好的 / 友好提示 | 提示什么文案？ | 提示「无可导出数据」，不产生文件；若涉及语气走查则写 `判定依据：ux-writing.md 三要素 + 判定人：designer` |
| 快速响应 / 稳定及时 | 多快？多稳？ | P95 < 500ms；导出成功率 > 99%，单次失败可重试 |
| 大量数据 | 多少算大量？ | 10000 行 |
| 适当的权限控制 | 谁能做什么？ | 主管可导出全组，客服仅自己的 |
| 尽可能保证一致 | 允许不一致吗？多久？ | 30 秒内最终一致；期间读到旧值可接受 |
| 必要时告警 | 什么条件？告给谁？ | 失败率 > 5% 持续 5 分钟，告 P2 给值班 |
| 体验良好 / 良好的用户体验 | 体现在哪个可观测点？ | 首屏 800ms 内出内容；加载中显示骨架屏（视觉还原度：`判定依据：prototypes/final/ + 判定人：designer`） |
| 支持扩展 | 现在有第二个场景吗？ | 无 → 删掉这条（YAGNI） |

**「支持扩展」这条特别值得删**：它不是需求，是技术偏好。真有第二个场景就写出来，没有就不写。

## 每条 FR 的最小 GWT 集

按风险选择适用场景，不规定条数；常见场景是：

```
① 正常路径 —— 一切顺利时的预期结果
② 空态或边界 —— 没数据 / 超上限 / 刚好在界上
③ 越权 —— 无权限的用户尝试时
```

按 FR 涉及的内容再追加：

| FR 涉及 | 必须补的 GWT |
|---|---|
| 列表/查询 | 空结果、分页边界（第一页/最后一页）、筛选无匹配 |
| 输入表单 | 必填缺失、超长、非法格式、特殊字符 |
| 状态流转 | 合法流转和按风险/等价类选择的非法流转 |
| 并发操作 | 两人同时操作同一对象 |
| 外部依赖 | 依赖不可用时的降级行为 |
| 批量操作 | 部分成功（不是全成功也不是全失败） |
| 权限相关 | 每个角色一条 + 越权一条 |
| 文件上传/下载 | 空文件、超大文件、格式不符 |
| 时间相关 | 跨时区、跨天边界、夏令时（如涉及） |
| 金额相关 | 0、负数、精度边界、多币种 |

**部分成功是最常被漏的**：批量导出 30 条，28 条成功 2 条失败——显示什么？文件里有几行？这个问题不在 PRD 里回答，开发就会自己随便选一个。

## 状态流转的 GWT 写法

涉及状态的 FR，合法与非法都要写。非法流转是 QA 的重要输入；QA/开发仍需设计并发、竞态等技术负向测试。

```
合法流转：
GWT-03.1  Given 订单处于 pending
          When  支付回调成功
          Then  订单变为 paid，记录 paid_at 为回调时刻

非法流转：
GWT-03.5  Given 订单处于 canceled
          When  支付回调到达
          Then  订单保持 canceled，回调被记录为「迟到回调」，不扣库存
```

非法流转的 Then 要写清楚**三件事**：状态保持不变、有无记录、有无副作用。只写「拒绝」不够——拒绝之后系统是什么状态？

## 同一动作只有一个 oracle

两条 GWT 可以覆盖同一屏幕的**不同动作**（打开页 vs 提交写）。相同 Given/When 下的结果必须兼容；一个动作可以有多个相关可观测效果。

实锤（一次真实审查）：一条 FR 冻结「租户打开渠道页 = 与 404 相同」，另一条仍写「租户查看渠道页 Then 密钥掩码」。审查按文件判，不采信变更表自批。

交货前：把「打开 / 查看 / 进入」同一对象的 When 列在一起，Then 必须能同时成立。NFR 一行摘要、权限矩阵、metrics-blueprint 护栏表同此——冲突时改短句，不要并存。

这份流转图必须与 `dba` 的 `db-spec.md` 第 2.1 节一致。两边不一致时以 PM 为准（业务规则归 PM），但要显式同步。

## 完整示例

```
FR-01 客服主管批量导出未结工单（旅程：J-1 第 1 步｜挂靠目标：metric:weekly_recon_ontime_rate@v1）

GWT-01.1 正常路径
  Given 主管角色已登录，本周有 30 条未结工单
  When  在列表页全选并点击「导出」
  Then  下载得到 CSV 文件，含 30 行数据
        列为「工单号/标题/创建时间/负责人」，按创建时间倒序
        文件名格式 tickets_YYYYMMDD.csv
  判定标准：CSV 数据行数 == 30，表头四列完全一致，created_at 单调非递增

GWT-01.2 空态（含定性逃生舱示例）
  Given 本周无未结工单
  When  点击「导出」
  Then  显示空态引导卡片与文案「无可导出数据」，不产生文件
  判定标准：下载请求 0 次；空态插图与文案层级由判定依据 `edge-states.md §屏1空态` + 判定人 `designer`（`04-verify/accept-design.md`）走查确认
```

GWT-01.3 数据量边界
  Given 选中 10000 条工单（上限）
  When  点击「导出」
  Then  10 秒内开始下载
  
GWT-01.4 超上限
  Given 选中 10001 条工单
  When  点击「导出」
  Then  提示「单次最多导出 10000 条，请缩小筛选范围」，不产生文件

GWT-01.5 越权
  Given 客服角色（非主管）已登录
  When  尝试导出他人负责的工单
  Then  返回 403，导出不执行，行为记入审计日志

GWT-01.6 部分失败
  Given 选中 30 条，其中 2 条在导出过程中被他人删除
  When  导出执行
  Then  文件含 28 行；页面提示「2 条已被删除，未包含在文件中」

GWT-01.7 敏感信息（对应 NFR-合规）
  Given 工单含联系人手机号
  When  导出
  Then  文件中手机号为 138****5678 格式
```

七条覆盖：正常、空态、边界、超限、越权、部分失败、合规。这个密度才叫「可测」。

## 已验证的跨项目教训

来自用户项目的逃逸记录，已去掉项目细节；项目自身的事实记在该项目的 `.sdlc/_lessons.md`。

- **用户可见的 Then 不出现内部错误码。** 测试可以断言错误码；用户看到的是「已达上限」和下一步能做什么。
- **同一条可见性规则只写一次。** 两个入口各自定义「已发布 / 可见」会各自漂移；写成一条产品规则，同时作废旧测试里各自的金标。
- **页面迁移时，验收跟着迁。** 旧页上已验收的能力（包括「不可信正文按纯文本显示」这类安全用例）在新页必须有对应的 GWT，不能写「沿用旧页即可」。
- **卖点只写合同允许的字面量。** 「能用 Excel 打开的 CSV」不是 Excel 导出；对外表述以真实的导出格式和测试为准。

## 自检

- [ ] 双向非孤儿追溯成立：每条 FR 向上挂靠 `metric:<id>@v<n>` 或 `A-n`（零镀金孤儿 FR），向下有可验证 GWT/评测行（零裸 FR）
- [ ] 每条验收项具备 `前提(Given) — 操作(When) — 预期结果(Then) — 判定标准` 四段
- [ ] 纯定性项显式写明 `判定依据 + 判定人`，且全文零禁用模糊词（`体验良好`、`稳定及时`、`友好的`、`gracefully` 等）
- [ ] When 是单个动作；Given 包含具体数据状态，不只是「已登录」
- [ ] 每条 FR 的适用风险（非法流转、批量部分成功、外部依赖降级）有可观测验收场景
- [ ] 交给 `qa` 后不需要回来问问题
