# GWT 验收标准写法

## 判定标准

一条 GWT 合格的唯一检验：**`/qa` 拿着它能直接写出用例，不需要回来问任何问题。**

需要回来问 = 不合格。常见的「需要回来问」：判断阈值多少、异常时显示什么、谁有权限、数据从哪来。

## 三段各自的职责

```
Given  前置状态 —— 系统处于什么状态、用户是谁、数据是什么
When   触发动作 —— 用户做了一个具体操作（一个，不是一串）
Then   可观测结果 —— 能被看到或测到的变化
```

三段各自的常见错误：

| 段 | 错误 | 修正 |
|---|---|---|
| Given | 「用户已登录」（太粗） | 「主管角色已登录，本周有 30 条未结工单」 |
| Given | 写了动作（「用户点击了列表」） | 前置状态不是动作，动作放 When |
| When | 一串操作（「登录后进入列表选中导出」） | 拆成 Given（已登录、已在列表）+ When（选中并导出） |
| When | 描述内部实现（「调用导出接口」） | 用户视角：「点击导出按钮」 |
| Then | 「导出成功」（不可观测） | 「下载得到 CSV 文件，含 30 行数据」 |
| Then | 描述实现（「写入 export 表」） | 用户能看到什么 |
| Then | 多个无关结果堆一条 | 拆成多条 GWT |

## 不可测词改写对照

出现这些词必须改写。改写方法统一是**问「怎么算」**：

| 不可测词 | 追问 | 改写 |
|---|---|---|
| 正确显示 | 正确是什么样？ | 显示「工单号/标题/创建时间/负责人」四列，按创建时间倒序 |
| 合理处理 | 具体怎么处理？ | 保留已成功的 28 条，失败的 2 条列出原因 |
| 友好提示 | 提示什么文案？ | 提示「无可导出数据」，不产生文件 |
| 快速响应 | 多快？ | P95 < 500ms |
| 大量数据 | 多少算大量？ | 10000 行 |
| 适当的权限控制 | 谁能做什么？ | 主管可导出全组，客服仅自己的 |
| 尽可能保证一致 | 允许不一致吗？多久？ | 30 秒内最终一致；期间读到旧值可接受 |
| 必要时告警 | 什么条件？告给谁？ | 失败率 > 5% 持续 5 分钟，告 P2 给值班 |
| 良好的用户体验 | 体现在哪个可观测点？ | 首屏 800ms 内出内容；加载中显示骨架屏 |
| 系统稳定 | 什么指标？ | 导出成功率 > 99%；单次失败可重试 |
| 支持扩展 | 现在有第二个场景吗？ | 无 → 删掉这条（YAGNI） |

**「支持扩展」这条特别值得删**：它不是需求，是技术偏好。真有第二个场景就写出来，没有就不写。

## 每条 FR 的最小 GWT 集

按风险选择适用场景，不规定条数；常见场景是：

```
① 正常路径 —— 一切顺利时的预期结果
② 空态或边界 —— 没数据 / 超上限 / 刚好在界上
③ 越权 —— 无权限的用户尝试时
```

按 FR 涉及的内容再追加：

| FR 涉及 | 必须补的 GWT |
|---|---|
| 列表/查询 | 空结果、分页边界（第一页/最后一页）、筛选无匹配 |
| 输入表单 | 必填缺失、超长、非法格式、特殊字符 |
| 状态流转 | 合法流转和按风险/等价类选择的非法流转 |
| 并发操作 | 两人同时操作同一对象 |
| 外部依赖 | 依赖不可用时的降级行为 |
| 批量操作 | 部分成功（不是全成功也不是全失败） |
| 权限相关 | 每个角色一条 + 越权一条 |
| 文件上传/下载 | 空文件、超大文件、格式不符 |
| 时间相关 | 跨时区、跨天边界、夏令时（如涉及） |
| 金额相关 | 0、负数、精度边界、多币种 |

**部分成功是最常被漏的**：批量导出 30 条，28 条成功 2 条失败——显示什么？文件里有几行？这个问题不在 PRD 里回答，开发就会自己随便选一个。

## 状态流转的 GWT 写法

涉及状态的 FR，合法与非法都要写。非法流转是 QA 的重要输入；QA/开发仍需设计并发、竞态等技术负向测试。

```
合法流转：
GWT-03.1  Given 订单处于 pending
          When  支付回调成功
          Then  订单变为 paid，记录 paid_at 为回调时刻

非法流转：
GWT-03.5  Given 订单处于 canceled
          When  支付回调到达
          Then  订单保持 canceled，回调被记录为「迟到回调」，不扣库存
```

非法流转的 Then 要写清楚**三件事**：状态保持不变、有无记录、有无副作用。只写「拒绝」不够——拒绝之后系统是什么状态？

## 同一动作只有一个 oracle

两条 GWT 可以覆盖同一屏幕的**不同动作**（打开页 vs 提交写）。相同 Given/When 下的结果必须兼容；一个动作可以有多个相关可观测效果。

实锤（feat-four-pillars QA-29）：FR-07 冻「租户打开渠道页 = 与 404 相同」；FR-14 仍写「租户查看渠道页 Then 密钥掩码」。审查按文件判，不采信变更表自批。

交货前：把「打开 / 查看 / 进入」同一对象的 When 列在一起，Then 必须能同时成立。NFR 一行摘要、权限矩阵、metrics-blueprint 护栏表同此——冲突时改短句，不要并存。

这份流转图必须与 `/dba` 的 `db-spec.md` 第 2.1 节一致。两边不一致时以 PM 为准（业务规则归 PM），但要显式同步。

## 完整示例

```
FR-01 客服主管批量导出未结工单

GWT-01.1 正常路径
  Given 主管角色已登录，本周有 30 条未结工单
  When  在列表页全选并点击「导出」
  Then  下载得到 CSV 文件，含 30 行数据
        列为「工单号/标题/创建时间/负责人」，按创建时间倒序
        文件名格式 tickets_YYYYMMDD.csv

GWT-01.2 空态
  Given 本周无未结工单
  When  点击「导出」
  Then  提示「无可导出数据」，不产生文件

GWT-01.3 数据量边界
  Given 选中 10000 条工单（上限）
  When  点击「导出」
  Then  10 秒内开始下载
  
GWT-01.4 超上限
  Given 选中 10001 条工单
  When  点击「导出」
  Then  提示「单次最多导出 10000 条，请缩小筛选范围」，不产生文件

GWT-01.5 越权
  Given 客服角色（非主管）已登录
  When  尝试导出他人负责的工单
  Then  返回 403，导出不执行，行为记入审计日志

GWT-01.6 部分失败
  Given 选中 30 条，其中 2 条在导出过程中被他人删除
  When  导出执行
  Then  文件含 28 行；页面提示「2 条已被删除，未包含在文件中」

GWT-01.7 敏感信息（对应 NFR-合规）
  Given 工单含联系人手机号
  When  导出
  Then  文件中手机号为 138****5678 格式
```

七条覆盖：正常、空态、边界、超限、越权、部分失败、合规。这个密度才叫「可测」。

## 自检

- [ ] 每条 GWT 的 Then 是可观测的（能看到或测到）
- [ ] 无不可测词
- [ ] When 是单个动作
- [ ] Given 包含具体数据状态，不只是「已登录」
- [ ] 每条 FR 的适用风险有可观测的验收场景
- [ ] 涉及状态的 FR 写了非法流转
- [ ] 涉及批量的 FR 写了部分成功
- [ ] 涉及外部依赖的 FR 写了降级行为
- [ ] 交给 `/qa` 后他不需要回来问问题
