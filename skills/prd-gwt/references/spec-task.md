# Define / spec entry

Purpose: turn already authorized scope into observable business behavior. This task does not establish that a build works or approve a later scope change.

Read the packet's pinned briefing when applicable, product strategy/feature map, decision record and measurement facts. Reuse earlier authorization with its source. L1 can start from the supplied intent and narrow facts; L2+ can reuse an accepted customer brief. If a consequential value/scope decision remains unresolved, identify its owner and blocked requirements. Do not invent an approval or send every settled detail back to discovery.

For 0→1, fill owned product templates with facts and explicitly labelled hypotheses. A metrics proposal with no baseline can be valid planning input; an invented baseline cannot. Read product-shaping for value/solution choices, gwt-authoring for business oracles, and metrics-blueprint only when measurement changes. Stage accept uses its separate build walkthrough.

When missing understanding prevents definition, use the [discussion protocol](../../discover/references/discuss-protocol.md). Return a helpful scenario, comparison or rule/example question to the manager with its blocked consumers; do not require the user to supply a finished PRD. A correction revises only affected decisions and their downstream impact. Resume from existing answers and rejected alternatives.

Example: the user has authorized CSV export for support leads, using the existing tenant permission model. Preserve that choice. Specify visible success/failure, denied access, empty results and limits; a newly discovered retention-policy question blocks its dependent behavior, not the already decided file format.

Completion: FRs refer to journeys and consistent observable outcomes, applicable measurement/scope gaps are explicit, and each unresolved decision names owner and blocked work. Write only declared files. Product strategy/feature-map are read-write inputs when authorized; return their post-change deltas. For v3, include every structured return field with input IDs and reported method use. A mechanically complete spec still needs independent review.
