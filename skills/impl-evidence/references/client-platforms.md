# 非 Web 端：原生、桌面壳与小程序

仅当已接受的功能切片目标是原生移动端（iOS/Android）、桌面壳（Electron、Tauri 或原生桌面）或小程序时阅读。纯 Web、API 或数仓任务不读本文件，也不因此增加阶段、角色、必填工件或测试要求。

只覆盖这次改动碰到的端。模拟器或预览器能证明的，和必须真机或标成 `unverified` 的，分开写。

## 打包、签名与权限声明

构建命令、工具链或锁文件、产物标识要能再次打出同一份包。Entitlements 或 Manifest 只声明这次功能用到的能力。相机、相册、本地文件、剪贴板、系统托盘等敏感能力，声明和运行时申请必须一致：声明了却从不申请，或运行时申请了声明里没有的项，都是缺漏。

## 系统权限拒绝、回收与降级

以下路径都要实测并留下命令或操作记录和结果，不能用「用户会允许」代替：

- 首次拒绝后的可用路径
- 用户在系统设置里再次撤权后的表现
- 弱网或离线冷启动
- 后台切回前台时的状态恢复

做不到的路径写 `unverified`、缺什么、谁补。不要把授权成功的主路径写成已经覆盖了拒绝和回收。

## 跨层桥接

WebView、JSBridge、IPC、Deep Link 和自定义协议 URL 都是不可信输入。命令、来源和路径走白名单，只暴露该切片需要的面。桥上的载荷不能直接当成已经授权的用户操作。

## 真机与模拟器、预览器

模拟器、开发工具预览能证明界面布局和本地逻辑。推送、相机、蓝牙、系统权限弹窗、安装签名和平台审核限制，必须真机或对应的签名、提交流程；否则标 `unverified`。不得用模拟器或预览器通过冒充真机就绪。小程序开发者工具预览同此界限。

## 定向回归

只跑受改模块、桥接契约和目标端关键旅程的定向构建与验证。禁止为了这个端去跑仓库全量测试或全量端到端，除非操作者明确要求。
