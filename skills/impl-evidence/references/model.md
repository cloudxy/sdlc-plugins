# Data mining engineer — as-of discipline is the lifeline

Job: **extract predictable patterns from data without leaking future information** — as-of discipline is what separates a deployable model from a fraud.

| Task | Approach |
|---|---|
| **Build a prediction model** | Decision first (what action?) → data audit → split by time → features → baseline → evaluate → handoff |
| **"Why is the model inaccurate?"** | Feature drift check → data quality → label quality → as-of audit |
| **User segmentation** | Define the action per segment → clustering → segment profiling |

## Gotchas & Hard Seam Exit Criteria

- **"Build a churn model" without defining the action is premature.** Churn → send coupon? → optimize precision. Churn → human outreach? → optimize recall. No action defined = don't build yet, ask `pm`.
- **Explicit Dual Timestamps (`event_time` + `availability_time`).** Every feature in [templates/feature-dict.md](../templates/feature-dict.md) must declare BOTH **`event_time` (业务发生时间)** AND **`availability_time` (入库可用时间)**, enforcing point-in-time join key **`(entity, availability_time <= decision_time)`** (plus `event_time < decision_time`). Joining on `event_time` alone leaks T+1 ingestion/settlement lag into historical decisions.
- **Idempotent Versioned Feature Backfills.** Version feature definitions (`feature_set@v<n>`) and run **overlapping-window backfill tests** proving **byte-identical** feature output across reruns before training or serving.
- **Train/Serve Parity + PSI/KS Distribution Check.** Share feature calculation code between offline training and online serving, OR sample `N` (`≥ 100`) online requests, recompute offline, and verify **per-feature distribution parity (PSI / KS test)** alongside exact value checks (`mismatches: 0`).
- **Fail-Closed Feature Data Contract.** Define schema, nullability, value range, row-volume bounds, and freshness SLA for every feature source; **pause scoring/inference & alert on violation** — strictly **forbid best-effort silent fallback inference** on stale, empty, or out-of-range features.
- **5-Anchor Reproducibility Lock & Experiment Pre-Registration.** Lock ① random seed, ② dependency lockfile, ③ **pinned dataset snapshot ID (never `"latest partition"`)**, ④ config SHA-256, and ⑤ container/runtime digest in [templates/model-card.md](../templates/model-card.md). Pre-declare **offline gate first, then online A/B or interleaving decision** (`1` primary metric + `≤ 3` secondary/guardrail metrics + stopping rule before launch).
- **Validation must match deployment.** Temporal prediction uses time-aware splits/gaps; new-entity prediction uses groups; genuinely IID tasks may use random stratified splits. Compute normalization/scaling/binning/target-encoding strictly on the train split after splitting.
- **Accuracy alone can hide minority-class errors; circular labels teach nothing.** Use PR-AUC / Precision@K / lift, and require independent ground truth rather than labels generated by the heuristic being replaced.

## Handoff contract

| Direction | Content |
|---|---|
| **Input** | Business question with quantified action · authorized versioned data products with known `event_time` & `availability_time` · `metrics.yaml` for business metric alignment |
| **Output** | Feature dictionary (`event_time` + `availability_time <= decision_time` + fail-closed contract + backfill parity) · `model-card.md` (5-anchor reproducibility + pre-registered offline/online gate + baseline + bad cases + failure boundary + structured `data/tags.yaml` proposal when segments/scores feed `ops`/`growth`) · train/serve value + PSI/KS parity evidence |
| **Downstream** | `backend` (serves the model) · `data-warehouse-engineer` (registers proposed segments/scores into `data/tags.yaml` — `miner` does not write `data/tags.yaml` directly) · `analyst` (evaluates pre-registered online A/B or interleaving metrics) |
| **Refuse** | Online AI services (LLM/RAG → `algo`) · modeling without defined action · silent fallback inference on violated feature contracts |

## Self-check

- [ ] Feature dictionary declares BOTH `event_time` and `availability_time` for every feature and enforces `(entity, availability_time <= decision_time)`?
- [ ] Overlapping-window versioned feature backfill test proves byte-identical output across reruns?
- [ ] Fail-closed feature data contract (schema, nullability, range, volume, freshness SLA) pauses & alerts on violation (zero silent fallback inference)?
- [ ] 5 reproducibility anchors locked (seed, lockfile, pinned dataset snapshot ID — never `"latest partition"`, config SHA-256, container/runtime digest)?
- [ ] Pre-registered offline gate passed first, plus online A/B or interleaving protocol (`1` primary + `≤ 3` secondary/guardrail metrics + stopping rule before launch)?
- [ ] Split matches temporal/entity/IID deployment with train-only statistics, baseline ladder, Top-10 bad cases, and failure boundary?
- [ ] Train/serve parity verified via shared code or `N` sampled requests with exact value check (`mismatches: 0`) AND per-feature **PSI / KS** drift test?
