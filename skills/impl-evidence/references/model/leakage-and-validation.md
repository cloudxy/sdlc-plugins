# 泄漏排查与验证策略

## 为什么泄漏是最危险的失败

泄漏**不报错**。它给你一个漂亮的离线分数，然后上线就崩。而且崩的时候你会先怀疑工程实现、怀疑数据管线，最后才想到是特征本身有问题——期间可能已经浪费了几周。

**症状：离线分数好得可疑。** 真实业务问题的流失预测 AUC 通常在 0.75–0.88；见到 0.97 先查泄漏，不要庆祝。

## 五类泄漏

### ① 时间泄漏（最常见）

特征包含了 as-of 时刻之后的信息。

```sql
❌ SELECT user_id, COUNT(*) AS total_orders
     FROM orders GROUP BY user_id           -- 全期订单，含未来

✅ SELECT user_id, COUNT(*) AS orders_30d_before_asof
     FROM orders
    WHERE created_at <  :asof
      AND created_at >= :asof - INTERVAL 30 DAY
    GROUP BY user_id
```

**每个特征的 SQL 里都必须出现 `< :asof`。** 没有这个条件的聚合特征，默认怀疑它泄漏。

隐蔽形态：

```
❌ days_since_last_login  用 CURRENT_DATE 算 —— 相对「今天」而非 as-of
✅ DATEDIFF(:asof, last_login_before_asof)

❌ user.updated_at        用户表的更新时间戳 —— 可能因未来事件而更新
❌ user.status            当前状态 —— 可能已经因流失而变更
```

**维度表的当前状态字段是隐蔽泄漏源**：`user.status = 'churned'` 这种字段直接包含了答案。用快照表或事件流重建 as-of 时刻的状态。

### ② 切分前统计变换

```
❌ scaler.fit(全量数据)        # 均值/标准差包含了测试集信息
   X_train, X_test = split(...)

✅ X_train, X_test = split(...)
   scaler.fit(X_train)         # 只用训练集统计量
   X_test = scaler.transform(X_test)
```

同类问题：目标编码（target encoding）、缺失值填充的均值、分箱边界、特征选择——**任何用到统计量的操作都必须只在训练集上拟合**。

时序场景更严格：**训练集的统计量本身也应该是滚动的**（用 as-of 之前的数据算），否则训练集内部也有轻微泄漏。

### ③ 标签泄漏（最难发现）

特征与标签由同一个业务动作产生。

```
预测流失，特征里有「是否已发挽留券」
→ 运营给判断可能流失的用户发券
→ 这个特征包含了「人已经判断他可能流失」的信息
→ 但在真实预测时刻，券还没发（正是要靠模型决定发给谁）
```

**排查方法**：看特征重要度 top-10，对每个问三个问题：

```
① 这个值是怎么产生的？（哪个业务动作写入的）
② 产生时间一定在 as-of 之前吗？
③ 在真实预测时刻，这个值一定已经存在吗？
```

第 ③ 问最关键。**「离线数据里有」不等于「预测时刻有」**。

同类形态：

- 预测订单取消，特征含「退款金额」（取消才会退款）
- 预测故障，特征含「工单数」（故障后才建工单）
- 预测转化，特征含「首购金额」（转化即首购）

### ④ 实体泄漏

同一个实体（用户/设备/店铺）同时出现在训练集和测试集。

```
❌ 随机切分 → 用户 A 的 6 月样本在训练集，7 月样本在测试集
   → 模型记住了「用户 A 的行为模式」，而非学到普适规律

✅ 按实体切分：用户 A 的所有样本只在一边
   或：时间切分 + 检查实体不跨集（多 as-of 点场景）
```

时间预测与新实体泛化是不同目标：为既有客户预测未来时可有同实体历史，但特征只能取当时可用事实；评估新客户时按实体分组。按部署目标选择，不同时强加两种分割。

### ⑤ 未来聚合

群体统计量用了全期数据。

```
❌ 特征「该用户所属城市的平均流失率」——用全期数据算
   → 包含了未来信息，且包含了该用户自己的标签

✅ 用 as-of 之前的数据算城市流失率，且排除当前用户自身
```

**「排除自身」这一点容易漏**：小群体里，群体均值几乎等于泄漏标签。

## 泄漏排查流程

发现分数可疑时按顺序查：

```
① 看特征重要度 top-10，逐个问三问（标签泄漏）
② 检查每个聚合特征的 SQL 是否有 < :asof（时间泄漏）
③ 检查切分与统计变换的顺序（切分前变换）
④ 检查实体是否跨集（实体泄漏）
⑤ 检查群体统计特征（未来聚合）
⑥ 做「时间倒推测试」：只用更早的特征窗重跑，分数应下降但不应崩塌
```

第 ⑥ 项只能提供调查线索：暴跌也可能来自有用近期信号丢失或分布变化，不能单凭下降幅度断定泄漏。

## 时序切分

### 基本形态

```
|--- 训练 ---|-- 验证 --|-- 测试 --|
2026-01~06    2026-07     2026-08
                                  ↑ 最新，最接近线上分布
```

**测试集必须是最新的时间段**——它要模拟「用历史训练，预测未来」的真实场景。

### 滚动窗口验证（更稳健）

单次切分的结果可能受特定时间段影响（大促、节假日、系统故障）。滚动验证给出更可靠的估计：

```
折 1：训练 01-04，测试 05
折 2：训练 01-05，测试 06
折 3：训练 01-06，测试 07
折 4：训练 01-07，测试 08
→ 报告各折分数与方差
```

**方差大说明模型不稳定**，可能对特定时期的模式过拟合。只报最好一折是误导。

### 训练窗口长度

| 情况 | 倾向 |
|---|---|
| 业务模式稳定 | 用更长的历史（更多数据） |
| 业务快速变化 | 用较短的近期数据（旧模式已失效） |
| 有明显季节性 | 至少覆盖一个完整周期 |

**测一下**：分别用 3/6/12 个月训练，比较测试集表现。用旧数据反而更差时，说明业务在漂移，重训频率要提高。

## 指标选择决策树

```
有标签吗？
├─ 无 → 无监督（分群/异常），见 segmentation.md
└─ 有 ↓
   类别平衡吗？
   ├─ 平衡（少数类 > 30%）→ ROC-AUC / F1 / 准确率可用
   └─ 不平衡 ↓
      下游有处理能力上限吗？
      ├─ 有（每天只能处理 N 个）
      │   → **Precision@K / lift@top-N%**（最贴合业务）
      └─ 无（全量打分，按概率分档）
          需要概率本身可信吗？
          ├─ 是 → PR-AUC + **校准曲线**
          └─ 否 → PR-AUC
```

### 为什么不平衡下 ROC-AUC 会误导

ROC-AUC 用假正率（FPR = FP / 全部负例）。负例极多时，即使 FP 绝对数很大，FPR 仍然很小——ROC 曲线看起来很好，但实际上 top-N 里混了大量误报。

PR 曲线用精确率（TP / (TP + FP)），直接反映「报出来的里面有多少是真的」，在不平衡场景下更贴合业务感受。

### lift 的计算与解读

```
lift@top-5% = top-5% 样本中的正例率 / 整体正例率
```

| lift | 解读 |
|---|---|
| 1.0 | 模型无效（等于随机） |
| 2–3 | 有价值 |
| 5–10 | 效果好 |
| > 20 | **查泄漏** |

**lift 是最容易向业务解释的指标**：「前 5% 的用户流失概率是平均的 6 倍」——业务方能直接判断值不值得投入运营资源。

## 不平衡处理

| 手段 | 说明 | 注意 |
|---|---|---|
| 类别权重 | 模型参数里设 `class_weight` | 最简单，优先试 |
| 欠采样多数类 | 丢弃部分负例 | 丢信息；数据量大时可接受 |
| 过采样少数类 | 复制或 SMOTE 合成 | **只在训练集做**，验证/测试集保持真实分布 |
| 调整阈值 | 不改数据，改决策阈值 | 通常最有效且最简单 |

**先试「调整阈值」**：很多情况下模型排序能力已经够，只是默认 0.5 阈值不合适。按业务的精确率/召回率权衡选阈值。

**过采样绝不能在切分前做**——合成样本会跨越训练/测试边界，造成严重泄漏。

## 校准

需要概率可信时（按概率分档做不同力度的干预）必须检查校准：

```
校准曲线：把预测概率分箱，比较每箱的「平均预测概率」与「实际正例率」
理想情况：落在对角线上
树模型：通常偏离（概率被推向极端）
```

不校准的后果：模型说「80% 会流失」，实际只有 45% 流失——按 80% 的力度发券就浪费了预算。

只需要排序（top-N）时不必校准。

## 验证清单

- [ ] 每个聚合特征的 SQL 含 `< :asof`
- [ ] 无相对「今天」计算的时间差特征
- [ ] 维度表的当前状态字段未直接使用（用快照或事件流重建）
- [ ] 统计变换在切分之后，只用训练集拟合
- [ ] 特征重要度 top-10 逐个过了三问
- [ ] 实体分组符合所需泛化目标
- [ ] 群体统计特征 as-of 且排除自身
- [ ] 预测未来时采用时间切分；其他目标采用相应验证设计
- [ ] 做了滚动窗口验证，报告了各折方差
- [ ] 做了时间倒推测试（分数温和下降而非暴跌）
- [ ] 指标按决策树选择，不平衡下未用准确率
- [ ] 有处理能力上限时用 Precision@K / lift
- [ ] 过采样只在训练集做
- [ ] 需要概率可信时检查了校准曲线
- [ ] 与基线（常量/规则/简单模型）逐级对比

验证设计参考：[scikit-learn cross validation](https://scikit-learn.org/stable/modules/cross_validation.html)、[data leakage](https://scikit-learn.org/stable/common_pitfalls.html)。
