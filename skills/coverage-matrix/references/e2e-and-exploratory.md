# 关键旅程 E2E 与探索性测试

覆盖矩阵证明「每条需求都有用例」，但证明不了「用户能把事办成」。v4 的 verify 阶段必须同时回答后一个问题：**关键旅程在运行中的产品上端到端走得通**，以及**我们没想到的地方有没有坑**。

## 1. 关键旅程 E2E（J-n，强制）

### 覆盖什么

| 覆盖 | 不覆盖（下沉到集成/单元） |
|---|---|
| spec 里每条 J-n 的主干：从真实起点走到 Aha 时刻 | 每个边界值、每个错误码、权限矩阵每一格 |
| 旅程中最关键的一条「不顺利」路径（空数据 / 无权限 / 依赖失败后恢复） | 纯逻辑分支 |
| 签名时刻出现（元素可见、文案正确） | 像素级视觉（交给设计走查与视觉回归） |

每条 J-n 至少 1 条 E2E，通常 1–3 条。E2E 总量保持在个位数到十几条。

### 怎么写（以 Playwright 为例，按项目实际框架替换）

```ts
test('J-1 首次导入到看到报表', async ({ page }) => {
  await page.goto(`${BASE_URL}/signup`);           // 真实起点：新账号
  // … 注册、上传 fixtures/sample-5000.xlsx
  await expect(page.getByRole('heading', { name: '销售周报' })).toBeVisible({ timeout: 30_000 });
  await page.screenshot({ path: 'e2e-artifacts/j1-aha.png' });  // 证据
});
```

纪律：
- 用**用户可见的定位**（role、label、文本），不用脆弱的 CSS 选择器。
- 数据自给自足（每条用例自己准备账号与数据），可并行、可重跑。
- 等待「条件」而不是固定 sleep；超时值取自 NFR（如 Aha ≤ 30s）。
- 失败时自动截图 / 录像，路径写进矩阵。
- 在接近生产的环境跑（真实后端与数据库方言）；mock 的依赖在报告里列出。

### 结果记账

- 命令写进 `sdlc.config.yaml` 的 `gates.e2e`；经理跑完后在 `state.yaml` 记 `{name: e2e, kind: script, result: pass|fail, cmd, exit_code, at}`。
- **有界面的变更 e2e 不得为 null**（v4 闸门 `E2E`）。确实无法自动化时：写手工脚本 + 截图，结果仍记为一条 script 闸门，并在 `open_questions` 里给出补自动化的计划。

## 2. 埋点校验（EV-n）

每个 EV-n 在矩阵里有一行：触发了、只触发一次、属性正确、身份正确。方法见 `collect` 做法的 tracking-validation 参考。可在 E2E 中拦截上报请求断言事件与属性。

## 3. 探索性测试（风险驱动）

脚本化测试只能发现你想到的问题。每个 L2+ 功能至少安排 1 个 30–60 分钟的探索性测试会话，优先覆盖：新流程、金额、权限、并发、首次体验、移动端。

### 测试章程（charter）

```
探索 <目标区域>
使用 <资源：角色、数据、设备、网络条件>
以发现 <信息：哪类风险>
```

例：探索「报表分享」，使用「未登录访客 + 手机 375 宽 + 慢速 3G」，以发现「分享页在弱网和无权限时是否可用、是否泄露数据」。

### 会话记录（写进 test-report.md）

| 章程 | 时长 | 覆盖了什么 | 发现的问题（→ 缺陷单） | 疑问（→ pm/designer） | 下一轮建议 |
|---|---|---|---|---|---|

### 启发式清单（挑相关的用）

- **CRUD 全周期**：建、查、改、删、再建同名。
- **中断**：刷新、后退、断网、会话过期、双击提交、并发两个标签页。
- **边界数据**：空、1 条、上限、超长文本、emoji、从 Excel 粘贴的隐藏字符、时区与跨日。
- **角色切换**：同一对象在不同角色 / 租户下看。
- **首次体验**：全新账号、无数据、未完成引导。
- **可用性快检**（Nielsen）：系统状态可见、容错与撤销、一致性、识别优于回忆、错误信息说清下一步。

## 4. 可用性问题也是缺陷

探索中发现「功能对但用户会卡住」的问题（例如 Aha 前 20 秒无任何进度反馈），按缺陷单记录，严重度按对旅程的影响定级，并抄送 pm（验收走查会复核）。
