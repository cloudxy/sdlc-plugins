# 关键旅程 E2E 与探索性测试

覆盖矩阵证明「每条需求都有用例」，但证明不了「用户能把事办成」。v4 的 verify 阶段必须同时回答后一个问题：**关键旅程在运行中的产品上端到端走得通**，以及**我们没想到的地方有没有坑**。

## 1. 关键旅程 E2E（J-n，强制）

### 覆盖什么

| 覆盖 | 不覆盖（下沉到集成/单元） |
|---|---|
| spec 里每条 J-n 的主干：从真实起点走到 Aha 时刻 | 每个边界值、每个错误码、权限矩阵每一格 |
| 旅程中最关键的一条「不顺利」路径（空数据 / 无权限 / 依赖失败后恢复） | 纯逻辑分支 |
| 签名时刻出现（元素可见、文案正确） | 像素级视觉（交给设计走查与视觉回归） |

每条 J-n 至少 1 条 E2E，通常 1–3 条。E2E 总量保持在个位数到十几条。

### 怎么写（以 Playwright 为例，按项目实际框架替换）

```ts
test('J-1 首次导入到看到报表', async ({ page }) => {
  await page.goto(`${BASE_URL}/signup`);           // 真实起点：新账号
  // … 注册、上传 fixtures/sample-5000.xlsx
  await expect(page.getByRole('heading', { name: '销售周报' })).toBeVisible({ timeout: 30_000 });
  await page.screenshot({ path: 'e2e-artifacts/j1-aha.png' });  // 证据
});
```

纪律：
- 用**用户可见的定位**（role、label、文本），不用脆弱的 CSS 选择器。
- 数据自给自足（每条用例自己准备账号与数据），可并行、可重跑。
- 等待「条件」而不是固定 sleep；超时值取自 NFR（如 Aha ≤ 30s）。
- 失败时自动截图 / 录像，路径写进矩阵。
- 在接近生产的环境跑（真实后端与数据库方言）；mock 的依赖在报告里列出。

### 结果记账

- 命令写进 `sdlc.config.yaml` 的 `gates.e2e`；经理跑完后在 `state.yaml` 记 `{name: e2e, kind: script, result: pass|fail, cmd, exit_code, at}`。
- **有界面的变更 e2e 不得为 null**（v4 闸门 `E2E`）。确实无法自动化时：写手工脚本 + 截图，结果仍记为一条 script 闸门，并在 `open_questions` 里给出补自动化的计划。

## 2. 埋点校验（EV-n）

每个 EV-n 在矩阵里有一行：触发了、只触发一次、属性正确、身份正确。方法见 `collect` 做法的 tracking-validation 参考。可在 E2E 中拦截上报请求断言事件与属性。

## 3. 探索性测试（风险驱动）

脚本化测试只能发现你想到的问题。每个 L2+ 功能至少安排 1 个 30–60 分钟的探索性测试会话，优先覆盖：新流程、金额、权限、并发、首次体验、移动端。

### 测试章程（charter）

```
探索 <目标区域>
使用 <资源：角色、数据、设备、网络条件>
以发现 <信息：哪类风险>
```

例：探索「报表分享」，使用「未登录访客 + 手机 375 宽 + 慢速 3G」，以发现「分享页在弱网和无权限时是否可用、是否泄露数据」。

### 会话记录（写进 test-report.md）

| 章程 | 时长 | 覆盖了什么 | 发现的问题（→ 缺陷单） | 疑问（→ pm/designer） | 下一轮建议 |
|---|---|---|---|---|---|

### 启发式清单（挑相关的用）

- **CRUD 全周期**：建、查、改、删、再建同名。
- **中断**：刷新、后退、断网、会话过期、双击提交、并发两个标签页。
- **边界数据**：空、1 条、上限、超长文本、emoji、从 Excel 粘贴的隐藏字符、时区与跨日。
- **角色切换**：同一对象在不同角色 / 租户下看。
- **首次体验**：全新账号、无数据、未完成引导。
- **可用性快检**（Nielsen）：系统状态可见、容错与撤销、一致性、识别优于回忆、错误信息说清下一步。

## 同一内容的多个消费者

复刻或模块改动涉及详情、预览、复制、下载或手势时，按相关入口列出：目标对象/版本、实际使用的数据或字节、成功结果、失败反馈和输入方式。用同一固定样例逐项执行；合法的行为差异沿已接受的契约说明，不能只凭相似控件认定一致。

- 下载核实际文件、类型与版本，防止取了预览或另一种表示；复制核实际剪贴板结果，不能只看 toast；有指针/触屏手势要求时分别核对应输入。
- 写入失败时保留输入、显示真实失败并核可恢复性；按钮点击成功或 `finally` 执行不等于保存成功。
- 本地媒体交付按[资源消费方法](../../impl-evidence/references/local-media.md)分开检查目录、字节、读取地址和播放。若校验器语义不成立，记录检查器缺陷及修正后的适用范围，不能用一次批量报错认定所有文件坏了。
- UI、服务和验证器各自固定版本与环境。桌面播放、合成 DOM、HTTP 分段、完整解码分别支持对应结论；未测试的设备、真实手势或专业效果保留未知。

## 4. 可用性问题也是缺陷

对菜单/媒体/授权类改动，按风险选用：展开菜单→点击子项→完成内容操作；预览反复开关不改生成结果及各自下载；成员切换后操作版本一致；授权模式切换后状态灯、校验和请求通道一致；续载失败保留 cursor、显式重试、分类切换丢弃迟到响应。按各来源已接受的首批/追加/重置规则核分页，而非套一个统一页码控件。

共享浏览器被其他人或任务切换时，旧定位和“未变化”都不能算测试结果；重新观察当前页，必要时请求短暂保留专用标签，继续不依赖 UI 的工作。不要反复抢焦点、关闭别人的对话框，或把未完成的截图/交互写成通过。沿当前宿主允许的自动化方式操作，不因工具不可用改用被禁止的技术。

正式环境写入测试数据须有对应授权；优先在隔离环境验证。获准后沿真实 HTTP/CLI 与既有身份范围写入明确标记的数据，登记记录 ID、预期覆盖、回读结果及保留/清理决定；不另建无必要账号，不顺带删除用户数据。没有真实写入授权时，保留为只读/隔离证据。

探索中发现「功能对但用户会卡住」的问题（例如 Aha 前 20 秒无任何进度反馈），按缺陷单记录，严重度按对旅程的影响定级，并抄送 pm（验收走查会复核）。

## 共享控件跨页面的样式走查

共享控件被不同主题、页头或嵌套容器承载时，按实际影响选择宿主，在相同断点对照关闭、展开及适用的当前项、hover、focus、disabled 状态。对照触发器与相邻同级控件的尺寸/文字基线，以及浮层、普通条目和选中项；保留设计已声明的主次、危险或主题变体，不把“统一”理解成所有颜色相同。

当本次影响跨入口菜单或点击路径且实际页面可用时，执行一条“入口甲打开 → 子项进入入口乙 → 再次打开 → 返回”的相关路径。内容内操作只选本次相关且已授权的动作；若只影响导航呈现，核对导航目标即可。页面不可用时保留待验，不抢占浏览器或扩大测试范围。核对约定样式、操作目标及适用的关闭行为。必要时补受影响窄屏下的菜单边界和滚动。单页截图、组件复用或 DOM 测试通过均不能单独证明跨宿主样式一致；只记录实际测到的状态/浏览器，回归限定在受影响控件和消费者，不默认扩大到全站或全量测试。

## 持续配置与短提示

本次修改会重绘长表单、参数区或提示浮层时，按风险补以下场景：

- 在真实滚动宿主滚到中段，打开更多参数，连续选择两个下拉项，再等待相关异步状态返回。核值确已生效、外层视口没有非预期跳动、焦点与展开状态仍可继续操作；组件内存中保存 scrollTop 不代替此观察。
- 对已约定的自动消失提示，分别核等待期、渐隐期和移除后，并在等待/渐隐中手动关闭；重放“旧提示被新消息替换，旧回调随后执行”，确认新消息仍在。计时分支宜下沉可控时钟测试，位置、动效与关闭可达性在实际页面验证。
- 关闭提示后继续操作下一控件，核浮层没有改变布局或抢走编辑焦点。错误或恢复提示的保留策略沿其独立契约，不能用成功提示约定推导。

记录实际设备、宿主、时间点和观察范围；没有捕获渐隐帧、只有 DOM/时钟证据时，不把浏览器动画效果也写成通过。纯后端或无此交互的修改不增加这些场景。
