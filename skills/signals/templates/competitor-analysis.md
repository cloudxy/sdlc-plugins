## 功能拆解

### F-01 <功能名> —— 结论：**借鉴**

| 项 | 内容 |
|---|---|
| 他们怎么做的 | <批量导出，支持任务队列、断点续传、导出模板保存> |
| **他们的场景** | <代理商一次处理数百单，导出是日常主流程> |
| **我们的场景** | <内部客服一次几十单，导出是周期性操作> |
| 场景差异 | <量级差一个数量级；频次他们日常我们每周> |
| **借鉴什么** | <「批量」这个方向本身；导出模板保存这个细节（我们的用户也每次选同样的列）> |
| **不借鉴什么** | <任务队列与断点续传——我们的量级不需要这套复杂度> |
| 对应我们的信号 | S-01（批量导出缺失，89 人受影响） |
| 来源 | 试用（高） |

**借鉴的粒度要具体到功能点**，不是「学他们做批量导出」。

### F-02 <功能名> —— 结论：**回避**

| 项 | 内容 |
|---|---|
| 他们怎么做的 | <AI 智能工单分类，自动路由到对应团队> |
| 他们的场景 | <日均数万工单，类型上百种> |
| 我们的场景 | <日均数百工单，类型 5 种> |
| **为什么回避** | <① 我们的数据量支撑不起模型投入 ② 5 种类型规则就能覆盖 ③ 引入 AI 会带来评估集、降级链、成本监控等一整套负担> |
| 替代方案 | <规则分类（找 `/algo` 确认规则基线足够）> |
| 复审条件 | <工单类型超过 20 种，或日均超 5000 单时重新评估> |
| 来源 | 官方文档（高） |

**回避结论和借鉴结论一样有价值** —— 它防止团队盲目跟随。且要给**复审条件**，避免结论变成永久教条。

### F-03 <功能名> —— 结论：**差异化**

| 项 | 内容 |
|---|---|
| 他们怎么做的 | <导出 Excel 给外部方，外部方回填后再手工导入> |
| 同一个用户问题 | <与外部方协作处理工单> |
| **我们的差异化解法** | <外部协作者只读链接 + 在线回填，彻底去掉 Excel 往返> |
| 为什么我们能做得不同 | <我们的用户是内部团队，外部协作方数量少且固定，可以给账号/链接；他们面向大量不固定的代理商，做不了> |
| 代价 | <需要权限体系改造（`/architect` 估 8 人周）> |
| 对应我们的信号 | S-01 的访谈发现（导出后还有回填与录回环节） |
| 来源 | 试用（高） |

**差异化要说清「为什么我们能，他们不能」** —— 否则只是想做得更好，不是差异化。
