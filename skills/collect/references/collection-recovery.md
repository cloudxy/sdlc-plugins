# 采集任务的所有权、恢复与交付

在有共享账号/浏览器、持久任务、分段采集或异步落库时使用；普通一次性请求不需要引入同样的状态机或存储栈。

## 任务交接与业务断点

- 标明待领取、执行中、等待、完成/死信等项目实际状态的接管者和恢复路径。领取与持久保存执行中任务之间若有窗口，需原子接管、可回收租约或有依据的对账；原子弹出本身不保证任务不丢。保留执行权时不再创建另一个可执行队列副本；回队则按协议移交所有权，并使迟到的旧执行者失去提交资格。
- `pending` 若是唯一恢复材料，不能仅靠 TTL 删除。采用租约时定义过期后的回收者、重复执行检测与提交校验；稳定任务身份不同于 JSON 文本、队列 member 或本次进程 ID。
- 断点绑定业务单元与输入身份：如任务、来源实体、地区、月份、筛选条件、必要的契约版本。恢复先重新确认页面/会话与输入，再决定沿用已完成单元、重采一月或整项重做；不把屏幕坐标或页码独自当作业务事实。
- 请求和响应一起确认归属；切换筛选、模块、任务或回看时隔离迟到包。任务 namespace 不能补足缺失的请求身份；证据不足时保存为未确认，避免把候选响应写成当前单元结果。验证同时覆盖应接收与应拒绝的真实脱敏样本。

## 完成与交付

按批准的需求定义发布单元、必需模块/月份、错误状态与数据新鲜度。成功阶段标记不能替代完整性检查。区分 missing、failed、partial、confirmed-empty、published、landed 等适用状态；合法空结果有证据及下游可接管的表达。

完整性只证明指定条件通过，不自动证明源站全集、跨时点快照或消费端持久化。是否允许部分交付、何时切换正式版本由业务契约决定；“所有来源都必须完整后才发布”不是通用要求。

数据与 `unsynced`/游标的独立写入、迁移与清理都有中断窗口：指定恢复、对账、重放和最终接管条件。声明完成前指出数据实际到达哪一段。稳定事件 ID、回执、提交未知与清理顺序使用 [可恢复写入与确认](../../schema/references/recoverable-writes.md)，不要另造一份存储协议。

## 失败范围、预算与恢复

每个失败策略同时说明：可观测证据、影响范围、任务归属、是否允许重试/切换、等待期间行为、恢复条件。按共享依赖确定范围；共享账号失效停止所有依赖该账号的操作，独立健康来源仍可运行。关闭浏览器、保留会话、暂停类型和停止进程是不同决策；只有会话损坏或适用生命周期策略要求时才重建浏览器。

根据来源访问约定、观测风险和容量预算，在失败之前限速或让出任务；正常让出保留进度，不消耗失败重试次数。固定点击数、暂停几小时、次日恢复和随机回看都是项目参数；随机动作不能证明平台机制或保证无法识别自动化。

关键配额账本不可读/写时，停止依赖该计量的新增操作；不能把未知次数当作零，不能切换类型绕过共享账本故障。普通性能统计失败可按契约降级。软背压暂停新任务而让补传/清理继续；容量或依赖恢复后重新核对准入，避免只能等到次日的无依据停机。

验证至少选择实际存在的风险：领取中断、租约到期、重复进程、恢复时输入变化、迟到响应、合法空结果、缺必需月份、发布成功后确认丢失。保留独立健康来源和非关键诊断失败的对照场景。证据标记代码/输入版本、实际运行环境和保证边界，已知缺口使用既有风险表记录负责人及复审条件，不增加固定编号或额外闸门。
