# 埋点校验：上线前证明事件对，上线后持续证明它还对

## 上线前（qa 在 verify 阶段，EV-n 进覆盖矩阵）

每个 EV-n 至少验证四件事：

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 触发了 | 浏览器网络面板 / SDK 调试模式 / 服务端日志 / E2E 拦截请求 | 行为发生时出现 |
| 只触发一次 | 同上，重复刷新、返回、双击 | 次数符合定义（首次、每次、去重） |
| 属性正确 | 对照 tracking.md 的类型与允许值 | 必填齐全、类型正确、枚举值合法、无明文 PII |
| 身份正确 | 未登录 → 登录前后各做一次 | `anonymous_id` / `user_id` 符合打通规则 |

E2E 中可以拦截上报请求做断言（例如 Playwright `page.on('request')` 过滤上报域名，解析 payload 检查 `event` 与属性）。无法自动化的事件写手工步骤，并附截图。

覆盖矩阵写法：

| EV | 事件 | 用例 | 层 | 结果 |
|---|---|---|---|---|
| EV-1 | report_viewed | TC-E2E-03 拦截上报断言 | E2E | ✅ |

## 数仓侧验收（有数仓时）

- 预发环境数据落到 ODS 后，按事件名查最近 1 小时：条数与手工操作次数一致；属性空值率为 0（必填）。
- 公共属性齐全，`user_id` 与业务库一致。

## 上线后的数据质量监控

| 监控 | 规则 | 告警 |
|---|---|---|
| 量级突变 | 事件日量较过去 7 天同日均值 ±50% | 通知 data-collector |
| 零数据 | 关键事件 1 小时 0 条 | 立即告警 |
| 属性异常 | 必填属性空值率 > 1%；枚举出现未定义值 | 日报 |
| 版本分布 | 新版本上线后旧事件名仍大量出现 | 核对发版 |

## 常见坑

| 坑 | 表现 | 修正 |
|---|---|---|
| 单页应用路由切换不触发 | 只统计到首次进入 | 以「价值出现」而非页面加载为触发 |
| React 严格模式开发环境双触发 | 开发看到 2 次，生产 1 次 | 在生产构建验证 |
| 重试导致重复上报 | 次数虚高 | 事件带 `event_id`，数仓去重 |
| 广告拦截 | 客户端事件缺失 5–30% | 关键结果放服务端 |
