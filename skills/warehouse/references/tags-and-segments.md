# 用户标签体系与人群：让精准营销有数据底座

增长运营说「给近 7 天导入过数据但没看报表的人发一条提醒」时，如果数仓要花两天写 SQL，精准营销就只能停留在口号。标签体系把「人」变成可组合、可复算、有口径的数据资产。

## 1. 三类标签

| 类型 | 定义 | 例 | 复算方式 |
|---|---|---|---|
| 事实标签 | 直接统计的客观事实 | 注册渠道、最近一次访问时间、累计导入次数、当前套餐 | SQL 聚合，按天 / 小时刷新 |
| 规则标签 | 事实标签的业务规则组合 | 生命周期阶段、RFM 价值分层、是否活跃 | 规则写进 tags.yaml `logic`，版本化 |
| 模型标签 | 预测得分 | 流失风险、付费倾向 | miner 产出，带 model card、刷新周期、阈值 |

## 2. 生命周期（最常用、最先建）

| 阶段 | 规则（示例，按产品的 Aha 定义改） |
|---|---|
| 新用户未激活 | 已注册，未发生 Aha 事件 |
| 已激活 | 注册后 7 天内首次发生 Aha 事件 |
| 活跃 | 近 7 天发生过核心动作 |
| 沉默 | 已激活，14 天无核心动作 |
| 流失 | 60 天无任何事件 |
| 回流 | 流失后再次发生核心动作 |

**Aha 事件由 pm 在 strategy.md 定义**，生命周期标签必须引用它——否则「激活」的口径和产品价值脱节。

## 3. RFM 价值分层

| 维度 | 定义（按产品改） | 分档 |
|---|---|---|
| R 最近一次 | 距最近一次付费 / 核心动作的天数 | 分位数 5 档 |
| F 频次 | 近 90 天付费 / 核心动作次数 | 5 档 |
| M 金额 | 近 90 天付费金额（非付费产品可用使用量） | 5 档 |

组合成可行动的群：高价值活跃、高价值沉默（重点召回）、低价值高频（升级机会）、新近低频（激活）。

## 4. tags.yaml 每个标签必填

| 字段 | 为什么 |
|---|---|
| `id` · `type` · `values` | 可被 growth 在人群定义中引用 |
| `logic` | 口径唯一；改口径 = 改版本 |
| `source_events` / `source_tables` | 能追溯到埋点与业务表 |
| `refresh` | 触达时效（触发式营销需要小时级甚至实时） |
| `owner` | 出问题找谁 |
| `privacy` | public / internal / sensitive —— 决定能否用于触达 |
| `consumers` | 变更时通知谁 |

## 5. 数据落地

```
事件 ODS → DWD 事件明细（统一 user_id、去重、时区）
       → DWS 用户日汇总（user_id, date, 核心动作次数, 最近访问, 付费…）
       → ADS 用户标签宽表（user_id, lifecycle_stage, rfm_segment, churn_risk, … , updated_at）
       → 人群服务 / 导出（供触达系统按标签组合圈人）
```

- 标签宽表按 `user_id` 主键、按刷新周期覆盖写（幂等）。
- 保留标签快照（按天分区）以便复盘「触达当时这个人属于哪个群」。
- 触发式场景（行为发生后 10 分钟内触达）需要实时或准实时通道，写 ADR 决定是否引入流式计算。

## 6. 人群（segment）= 标签组合 + 排除规则

```yaml
segment: activated_no_report_7d
include:
  - lifecycle_stage in [activated, active]
  - evt_dataset_imported_7d >= 1
  - evt_report_viewed_7d = 0
exclude:
  - internal_user = true
  - marketing_opt_out = true
  - contacted_within_days(7) = true
size_estimate: 3200 (2026-09-17)
```

growth 在 `launch.md` 只引用 segment 定义与标签 id，不写 SQL。

## 7. 质量与合规

| 检查 | 规则 |
|---|---|
| 覆盖率 | 活跃用户中标签非空比例 ≥ 99% |
| 分布漂移 | 各取值占比周环比变化 > 30% 告警（可能是埋点或口径坏了） |
| 口径一致 | 同一标签只有一个 logic；看板与触达系统引用同一 id |
| 隐私 | sensitive 标签不进触达系统；未成年人、已退订用户默认排除 |
| 可解释 | 模型标签附 model card 与阈值依据 |

## 反模式

| 反模式 | 修正 |
|---|---|
| 运营每次提需求临时写 SQL 圈人 | 沉淀为标签与 segment 定义 |
| 标签口径散落在各个看板 | tags.yaml 唯一定义 |
| 只有人口属性标签 | 行为与生命周期标签才能驱动精准触达 |
| 标签从不复盘 | 与 growth 实验记录联动，淘汰无效标签 |
