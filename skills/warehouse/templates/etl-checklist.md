# ETL 上线检查清单

> 分层遵循项目实际采用架构（如轻量 `staging → marts/serving` 或四层 `ODS/DWD/DWS/ADS`）；不强加未采用的分层，但命名必须与粒度契约一致。

## 设计与契约（SVOT）
- [ ] 上游源表/事件契约已确认（OLTP 只读源 / `tracking-plan.yaml` 事件流 / 外部 staging 或 `ods_`）
- [ ] 目标表与项目分层约定一致（如 `staging/marts` 或 `dwd_/dws_/ads_`，无低层反向引用高层）
- [ ] 原子粒度与时间归属（`time_semantics`: `event_time` / `business_time` / `ingestion_time` 及迟到回溯窗）已声明
- [ ] 幂等键已确定（时间分区 + 业务唯一键，支持 CDC 更新与硬删除 tombstone）
- [ ] 关联指标/标签已登记至 SVOT（`metrics.yaml` / `tags.yaml` 的 `version` 与 `effective_from`）

## 实现与隔离
- [ ] 按选定重放策略写入（分区覆盖 `INSERT OVERWRITE` / 主键 `MERGE` / 不可变追加+确定性去重，严禁无去重裸 `append`）
- [ ] 增量水位与迟到/删除补偿逻辑正确（不单靠 `updated_at` 漏掉硬删除或同秒覆盖）
- [ ] 明文 PII 在进入明细/服务层前完成脱敏或令牌化；多租户键或系统上下文豁免已按授权配置
- [ ] 使用只读源库账号与错峰/副本隔离，无硬编码连接串或密钥，查询已在生产 SQL 方言验证

## 质量断言（四类必跑）
- [ ] 主键/幂等键唯一性检查（同粒度 `0` 重复）
- [ ] 必填字段、外键维度与关键时间戳非空检查
- [ ] **领域感知符号与守恒对账检查**（正向交易 ≥ 0，**退款/冲正/红字分录允许负值**且与原单关联，净额 `gross + refund == net` 与上游源表守恒；计划日期允许未来值）
- [ ] 行数与核心汇总量波动检查（相对上游源表及历史同期，超阈值告警阻断）

## 幂等验证与血缘
- [ ] 同分区/窗口连续双跑，`run1` 与 `run2` 结果集 `diff` 为空
- [ ] 中途失败重跑后输出与单次成功完全一致
- [ ] 上游血缘已登记，破坏性或口径变更已通知 `consumers`
