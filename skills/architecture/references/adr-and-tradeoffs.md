# ADR 与技术取舍

## 何时决策，何时复用

先找已接受的决策及其适用条件。条件未变且有证据支持时，引用 ADR 与版本，说明本次仍满足的约束和复审触发条件；不制造第二个方案，也不复制一份 ADR。

存在新的重要取舍时，比较可信的候选方案（包含保留现状/不做，如适用）。比较质量目标、交付成本、运行成本、故障模式、迁移/退出成本和不确定性。没有可行替代时说明硬约束和排除依据；不要为了数量造稻草人。高影响、跨团队或难以逆转的决定写 ADR，轻量可逆细节可记在契约中。

ADR 保留背景、证据、选定理由、被排除选项及原因、代价、权限与复审条件。先核对已有授权；新增业务范围、安全风险、不可逆代价交给决策负责人。实验失败本身不授予改需求的权限。

## 同步、异步与一致性

| 问题 | 必须说明 |
|---|---|
| 交互 | 调用方需要的是受理结果、完成结果还是进度？超时后如何查询最终状态？ |
| 原子性 | 哪些更新必须同时成功？事务实际覆盖哪些系统？ |
| 可见性 | 谁在何时读到什么版本？隔离级别、读副本、缓存是否影响读己之写？ |
| 失败 | 超时、重试、重复、乱序、依赖失效、补偿失败如何处理？ |

同步调用不保证强一致，异步处理也不否定任务内部事务。单库事务的原子性不等于所有副本/缓存读都实时一致。定义具体不变量、隔离和可见性，而不是用通信方式替代一致性模型。

异步流程要有重试/退避和截止、幂等、副作用恢复、失败终态/人工处理、进度与监控。延迟窗口和期间用户看到的状态须符合已批准的需求。

## 存储与唯一事实源

先拆事实，再评估同库或多存储。任务定义、终态、审计与协调（队列、抢占、租约）的访问模式可能不同；这不意味着它们必须使用两个产品。

- 查代码和部署证据确认已有拓扑；「可能有 Redis」只能是待验证假设。
- 低负载、事务要求合适时，一个关系库也能承担任务记录与协调。检验竞争、锁、恢复和轮询成本，不先排除它。
- 已有 Redis/队列若适合可以复用，但仍增加本业务的运行依赖、容量和故障处理义务。
- 多存储必须说明每个事实的唯一权威、派生副本、双写窗口、重放/对账和恢复。不是禁止一切副本，而是禁止无协调的多个权威。
- 判断索引/查询改进是否已足够，再增加缓存、搜索、数仓或其他存储。物理结构与索引交 DBA。

项目特有的已验证事实见 [auto-agents-pitfalls.md](auto-agents-pitfalls.md)，只对匹配的仓库使用，不当作通用默认值。

## 一致性与交付机制

| 机制 | 需要验证的保证与代价 |
|---|---|
| 单库事务 | 事务边界、隔离级别、约束和读路径；适合的场景优先保持简单 |
| Saga | 每步状态、补偿可行性、不能补偿的动作和人工恢复 |
| 事务 outbox | 业务变化与待发记录同事务；投递重试、保留、监控和消费者幂等另行保障 |
| 事件消费 | 交付范围、去重/顺序、消费提交与外部副作用之间的失败窗口 |
| 分布式事务 | 参与者支持、协调者故障、阻塞/超时、可用性及运营代价 |

任何「不丢」「恰好一次」都需注明系统边界和故障假设。outbox 不是无人运维也绝不丢失的魔法；消息去重不能自动保证外部付款/邮件等副作用恰好一次。

## 依赖、缓存与实验

依赖评估覆盖功能适配、维护/安全响应、许可证、供应链、传递依赖、锁定/更新策略和退出成本；不能仅因半年无提交判定不安全或不成熟。缓存评估读写比例、实际瓶颈、一致性窗口、失效、击穿与不可用时的行为，引用 DBA 的键治理方案。

实验方法、预算、证据和失败回流统一见 [lifecycle.md](lifecycle.md)。估算不是压测；单机结果不可外推为线上容量保证。性能阈值建议须回到 PM/设计确认业务影响，不直接改 FR。

## ADR 生命周期

`proposed` → 有权决策者接受后 `accepted`；改判写新 ADR，旧的标 `superseded by ADR-nn`；无替代但不再适用标 `deprecated`。保留历史正文与授权记录，勘误注明原因。accepted 表示决定已接受，**不等于已经实现或部署**；基线状态见 lifecycle。

技术语义参考：[HTTP 幂等](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)、[事务与读一致性示例](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis.html)、[事务 outbox](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)。具体技术能力以项目锁定版本及证据为准。
